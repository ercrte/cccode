# Agent Evaluation Framework Spec

## 背景
MewCode 已经具备终端 TUI、Agent Loop、工具调用、权限系统、上下文管理、Skill、子 Agent、团队协作、Hook、会话记忆和 mock Provider 测试能力。现有测试主要验证功能是否按预期工作，但还缺少一个面向“这个编程助手靠不靠谱、好不好用”的系统化评测工作区。

评测体系需要把一次 Agent 运行从多个维度转成可比较的结果，帮助判断模型、提示词、工具策略或上下文策略调整后是否让助手更可靠、更高效、更安全。用户希望在项目内建立独立评测区域，并由后续修改补充或调整具体指标。

## 目标
- 提供一个独立的 Agent 评测工作区，用于组织评测用例、运行评测、保存结果和生成报告。
- 建立一套默认评测维度，覆盖可靠性、可用性、安全性和效率，而不是只看最终文本是否相似。
- 支持用确定性 mock Provider 做离线回归评测，避免基础评测依赖真实模型、真实 API key 或网络。
- 让评测结果可读、可比较、可追溯，便于在提示词、工具或上下文改动前后对比。
- 保持评测体系可扩展，后续可以新增用例、指标和真实模型评测模式。

## 功能需求
- F1: 评测工作区必须能按用例组织 Agent 任务，每个用例应描述用户请求、初始环境、允许工具或模式要求、期望行为和评分标准。
- F2: 默认评测维度必须至少覆盖：任务完成度、工具使用合理性、代码或文件修改质量、验证充分性、安全与权限遵守、上下文/记忆连续性、错误恢复能力、交互体验、效率与成本、结果稳定性。
- F3: 每个评测维度都必须有明确含义、可观测证据和评分范围，避免只有主观一句话评价。
- F4: 评测运行后必须产出结构化结果，至少包含用例标识、各维度得分、总分、通过/失败状态、关键证据、运行耗时和错误信息。
- F5: 评测报告必须能汇总多条用例结果，展示总体得分、各维度均分、失败用例列表和需要人工复核的事项。
- F6: 评测体系必须支持确定性离线运行，能复用现有 mock Provider 或等价的本地模拟方式触发工具调用、工具失败、权限拒绝、多轮迭代和最终回复。
- F7: 评测体系必须支持至少一组初始用例，覆盖普通问答、只读代码搜索、多轮工具调用、文件修改与验证、权限拒绝后调整、上下文摘要或长上下文场景、Skill 或子 Agent 场景。
- F8: 评测结果必须保留足够的运行证据，包括模型可见请求摘要、工具调用序列、工具结果状态、最终回复、usage 或近似成本信息，使失败原因可以定位。
- F9: 评测命令必须提供清晰的退出状态：全部通过时成功退出，有用例失败或评测框架错误时失败退出。
- F10: 评测体系必须允许用户后续扩展或调整维度、权重和用例，而不需要改动 Agent 核心运行逻辑。
- F11: 评测不得绕过 MewCode 的权限、沙箱、工具调度、上下文管理和 Provider 抽象；评测应尽量从真实 Agent 行为入口观察结果。

## 非功能需求
- N1: 初始版本应以本地可重复运行为优先，不要求接入外部评测平台。
- N2: 初始离线评测应能在没有真实 API key 和没有网络的环境下运行。
- N3: 评测输出应同时适合人读和机器处理。
- N4: 评测用例应避免执行破坏性操作，涉及写文件的用例必须限定在临时或隔离目录。
- N5: 评测框架本身失败时应给出明确错误原因，不能把框架错误误报成 Agent 能力失败。
- N6: 评测结果中的敏感信息应被避免或脱敏，不能泄露 API key、用户私密配置或无关本地路径。
- N7: 初始实现应尽量复用项目已有测试、mock Provider 和配置加载能力，不引入重量级外部依赖。

## 不做的事
- 不在初始版本中评测所有公开编程基准或接入在线排行榜。
- 不承诺自动评分可以完全替代人工评审；主观维度可以标记为需要人工复核。
- 不训练或微调模型，不根据评测结果自动修改提示词或代码。
- 不要求真实模型评测稳定通过；真实模型模式只作为后续可选扩展。
- 不绕过权限系统执行危险命令、真实删除、真实推送、真实网络操作或不可逆副作用。
- 不把评测结果作为单元测试的替代品；单元测试仍负责验证确定性代码行为。

## 验收标准
- AC1: 项目内存在独立评测工作区，包含可读的使用说明、默认评测维度定义和至少一组初始评测用例。（覆盖 F1、F2、F3、F7）
- AC2: 用户可以运行一个本地离线评测入口，在无真实 API key 和无网络依赖下执行初始用例，并得到结构化结果与汇总报告。（覆盖 F4、F5、F6、F9、N1、N2）
- AC3: 评测结果能展示各维度得分、总分、通过/失败状态、运行耗时、错误信息和关键证据；失败用例能定位到工具调用、回复或验证环节。（覆盖 F4、F5、F8、N3、N5）
- AC4: 初始用例覆盖普通问答、只读代码搜索、多轮工具调用、文件修改与验证、权限拒绝后调整、上下文或长任务、Skill 或子 Agent 中的至少六类场景。（覆盖 F7、F11）
- AC5: 评测过程不会绕过权限、沙箱、工具调度、上下文管理和 Provider 抽象；写入类用例不会污染项目真实文件。（覆盖 F11、N4）
- AC6: 用户可以通过修改评测工作区内容新增用例或调整维度/权重，而不需要改动 Agent 核心运行逻辑。（覆盖 F10、N7）
- AC7: 评测说明明确区分自动评分和需要人工复核的维度，并说明真实模型评测的不稳定性和适用范围。（覆盖 F3、N6、不做的事）
