# JulyCode 工具系统 Spec

## 背景
JulyCode 当前已经具备终端全屏对话、流式回复、多轮上下文、OpenAI 协议和 Anthropic 协议支持，但仍停留在纯对话阶段。用户提出真实编程请求时，模型只能给出建议，不能查看项目文件、搜索代码、修改文件或执行命令。本阶段要让 JulyCode 具备第一版本地工具能力，使模型可以在一次用户请求中选择合适工具，系统执行后把结果返回给模型，再由模型基于结果给出回复。

本阶段只打通一次工具调用链路，不实现持续自主循环。模型收到一次工具执行结果后，JulyCode 允许它生成面向用户的最终回复；如果模型再次要求调用工具，系统必须停止继续执行并给出清晰提示。

## 目标
- JulyCode 可以向 OpenAI 和 Anthropic 两类模型协议暴露同一组本地工具。
- 模型可以根据用户请求选择读取文件、写入文件、修改文件、执行命令、按模式找文件或搜索代码内容。
- JulyCode 可以解析流式回复中的工具调用，拼接完整参数并执行对应工具。
- 工具执行结果可以以结构化形式回到对话上下文，让模型据此生成后续回复。
- 工具失败、超时或参数错误时，JulyCode 不崩溃，并把可理解的失败结果返回给模型和用户。
- 文件修改必须采用原文唯一匹配替换，避免模糊修改造成不可控变更。

## 功能需求
- F1: JulyCode 必须以一致的方式描述和管理所有本地工具；每个工具必须提供名称、用途说明、参数约束和可执行行为。
- F2: JulyCode 必须内置六个核心工具：读取文件内容、写入文件内容、按原文替换修改文件、执行本地命令、按模式查找文件路径、搜索代码内容。
- F3: JulyCode 必须能集中登记可用工具，并在发起模型请求时把当前可用工具转换为 OpenAI 和 Anthropic 各自可识别的工具描述。
- F4: 用户提交消息后，模型可以在流式回复中请求调用工具；JulyCode 必须能识别工具名称，并把分片到达的参数拼接成完整参数。
- F5: 当模型请求的工具存在且参数有效时，JulyCode 必须执行该工具，并把执行结果追加到当前对话上下文中，再让模型基于结果生成一次回复。
- F6: 本阶段每次用户请求最多允许一轮工具执行；如果模型在收到工具结果后的回复中再次请求工具，JulyCode 必须停止继续执行并显示可理解提示。
- F7: 工具执行必须有超时控制；执行超时、工具不存在、参数不合法、系统调用失败或文件操作失败时，JulyCode 必须返回结构化失败结果，而不是中断整个应用。
- F8: 工具结果必须区分成功和失败，并包含足够信息供模型调整下一步回复；失败结果必须说明失败类型和可读错误信息。
- F9: 读取文件工具必须在文件存在且可读时返回文件内容；当路径不存在、不是文件或无法读取时，必须返回清晰失败结果。
- F10: 写入文件工具必须能创建或覆盖目标文件内容；当目标路径无法写入时，必须返回清晰失败结果。
- F11: 修改文件工具必须按调用参数中的原文进行唯一匹配替换；匹配不到或匹配多次时不得修改文件，并必须返回清晰失败结果。
- F12: 执行命令工具必须返回退出码、标准输出和标准错误；命令超时或启动失败时，必须返回清晰失败结果。
- F13: 按模式找文件工具必须返回匹配到的文件路径列表；当没有匹配结果时，必须返回成功但结果为空的响应。
- F14: 搜索代码内容工具必须返回匹配位置和匹配文本摘要；当没有匹配结果时，必须返回成功但结果为空的响应。
- F15: 工具调用过程必须兼容 OpenAI 和 Anthropic 的流式响应；纯文本流式回复在未调用工具时仍保持现有体验。
- F16: 工具调用和工具结果必须进入当前运行期会话上下文，使最终回复能够引用刚刚执行的结果；退出后仍不要求持久化历史。
- F17: 当工具调用发生时，终端界面必须向用户展示当前正在调用的工具、执行完成状态和最终模型回复。

## 非功能需求
- N1: 工具系统必须保持供应商协议差异对上层交互不可见；同一个用户请求在 OpenAI 或 Anthropic 配置下应呈现一致的工具使用体验。
- N2: 工具执行失败不得导致 TUI 退出、会话状态损坏或后续输入不可用。
- N3: 工具结果中不得泄露配置密钥；错误信息必须延续现有脱敏要求。
- N4: 文件和命令工具的错误提示必须足够具体，使模型可以据此重试或向用户解释原因。
- N5: 流式文本体验不得因引入工具系统而退化；未触发工具调用时仍应尽快显示文本增量。
- N6: 本阶段实现范围必须限制在一次工具调用链路，不引入自动循环、计划器、权限确认系统、跨会话工具历史或插件系统。

## 不做的事
- 不实现自动 Agent Loop，也不让模型在收到工具结果后继续无限调用工具。
- 不实现多个连续工具步骤的自主编排。
- 不实现交互式命令、长期后台进程、PTY 会话管理或命令输入接管。
- 不实现权限确认、危险命令拦截策略、沙箱隔离策略或细粒度访问控制。
- 不实现跨启动的工具调用历史持久化。
- 不实现插件市场、第三方工具加载或用户自定义工具配置。
- 不实现图片、网页浏览、网络搜索或外部服务集成工具。

## 验收标准
- AC1: 启动 JulyCode 后，OpenAI 配置下的模型请求包含六个核心工具的可识别描述。
- AC2: 启动 JulyCode 后，Anthropic 配置下的模型请求包含六个核心工具的可识别描述。
- AC3: 当模型在流式回复中分片输出工具参数时，JulyCode 能拼接出完整参数并调用正确工具。
- AC4: 用户请求读取一个存在的文件时，模型可以调用读取文件工具，最终回复能够引用文件内容。
- AC5: 用户请求写入一个文件时，模型可以调用写入文件工具，目标文件内容符合请求，最终回复说明写入结果。
- AC6: 用户请求修改文件中的唯一原文时，模型可以调用修改文件工具，文件只发生预期替换，最终回复说明修改结果。
- AC7: 当修改文件工具匹配不到原文时，文件不被修改，工具结果清楚说明未匹配。
- AC8: 当修改文件工具匹配到多处原文时，文件不被修改，工具结果清楚说明匹配不唯一。
- AC9: 用户请求执行一个会成功退出的命令时，模型可以调用执行命令工具，最终回复能够引用退出码和输出。
- AC10: 当命令执行超时时，应用不崩溃，工具结果清楚说明超时，用户可以继续输入下一条消息。
- AC11: 用户请求按模式找文件时，模型可以调用找文件工具，最终回复能够列出匹配路径；没有匹配时最终回复能说明结果为空。
- AC12: 用户请求搜索代码内容时，模型可以调用搜索工具，最终回复能够引用匹配位置；没有匹配时最终回复能说明结果为空。
- AC13: 当模型请求不存在的工具或传入无效参数时，JulyCode 返回结构化失败结果，并允许模型生成可理解回复。
- AC14: 当模型在收到一次工具结果后再次请求工具时，JulyCode 不继续执行第二轮工具，并在界面中显示本阶段不支持连续工具调用。
- AC15: 未触发工具调用的普通聊天仍能流式显示文本回复，并保留多轮上下文。
- AC16: 工具调用期间，终端界面能展示工具名称和执行状态；执行完成后展示最终模型回复。
- AC17: 工具执行失败或供应商返回错误时，界面显示脱敏后的错误信息，输入区恢复可用。
