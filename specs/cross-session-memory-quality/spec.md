# JulyCode 跨会话记忆质量 Spec

## 背景
JulyCode 已具备会话持久化、自动笔记、用户级与项目级记忆索引，以及在模型请求前注入记忆索引的能力。当前自动笔记主要依赖模型自行判断创建、更新或跳过，已有测试验证了存储、索引和注入链路，但尚未用人工标注数据量化提取质量，也没有严格验证“启动空白新会话后，仅依赖长期记忆完成首轮任务”的实际效果。

本阶段在现有长期记忆能力上增加保守、可追溯的自动提取规则和专项评测体系。评测同时覆盖自动记忆提取质量与空白新会话的上下文继承效果，并区分可稳定运行的离线测试和使用真实模型的发布验收。

## 目标
- 自动提取明确、稳定且会影响未来行为的长期记忆，减少临时要求、猜测和敏感内容被误存。
- 对明确关键偏好采用高精度策略，确保关键偏好 Precision 不低于 98%，同时避免通过完全不提取来虚高指标。
- 使用版本化人工标注数据集计算自动记忆提取的 Precision、Recall 和 F1，整体 F1 不低于 85%。
- 启动 `julycode --new-session` 后不恢复历史消息，但仍自动继承同一项目的长期事实、长期约定、已确认技术决策和关键用户偏好。
- 使用成对基线评测量化空白新会话的首轮任务理解正确率和背景重复说明减少率。
- 通过确定性离线测试保证评测流程稳定，通过真实模型评测和 tmux 端到端场景提供发布验收证据。

## 术语与指标口径
- **长期记忆单元**：一条可独立判断真假的稳定信息，包括用户偏好、纠正反馈、项目事实、长期约定、已确认技术决策或参考资料。
- **关键偏好**：用户明确表达、会约束后续行为的长期要求，例如“始终使用中文回复”“禁止自动提交代码”“测试必须使用 pytest”。模型从行为推测的隐式偏好和仅对当前任务有效的要求不属于关键偏好。
- **空白新会话**：通过 `julycode --new-session` 创建的新会话。其普通消息历史为空，但允许加载项目指令和长期记忆。
- **首轮任务理解正确**：用户在空白新会话中只给出任务、不重复项目背景；JulyCode 的第一轮完整处理结果遵循该用例标注的全部必要背景，不违反禁止条件，也不要求用户重新提供长期记忆中已有的信息。内部多次模型迭代或工具调用仍视为同一轮。
- **背景重述需求**：JulyCode 明确要求用户再次提供一个已经在来源会话中确认、且完成当前任务确实需要的背景事实；仅请求新的任务参数不计入。
- **TP**：一个提取结果与一个人工标注长期记忆单元在含义、作用域、类别和长期有效性上均匹配。每个标注单元最多匹配一个提取结果。
- **FP**：提取结果无法匹配任何标注单元，或作用域、类别、长期有效性错误；同一事实的多余重复提取也计为 FP。
- **FN**：人工标注为应记忆、但没有匹配提取结果的长期记忆单元。
- **Precision**：`TP / (TP + FP)`；没有任何预测时记为 0，而不是 100%。
- **Recall**：`TP / (TP + FN)`。
- **F1**：`2 × Precision × Recall / (Precision + Recall)`；Precision 和 Recall 同时为 0 时记为 0。
- **首轮任务理解正确率**：`首轮任务理解正确的用例数 / 跨会话用例总数`。
- **背景重复说明减少率**：对同一组用例分别关闭和开启长期记忆，按 `(关闭记忆时的背景重述需求次数 - 开启记忆时的背景重述需求次数) / 关闭记忆时的背景重述需求次数` 计算。关闭记忆时需求次数为 0 的评测无效，不得判定达标。

## 功能需求
- F1: 自动记忆更新必须只沉淀用户明确表达或已由用户确认的长期信息；临时任务步骤、一次性格式要求、模型猜测、短期工具输出和闲聊不得被提升为长期记忆。
- F2: 关键偏好必须采用保守提取规则：必须存在可定位到用户原话的直接证据，且原话明确表达跨任务持续生效的行为约束；缺少直接证据时不得标记为关键偏好。
- F3: 每个自动提取结果必须保留来源会话、来源证据、记忆类别、用户级或项目级作用域，以及是否属于关键偏好的可审查信息。
- F4: 自动提取不得保存凭据、令牌、私钥或其他明显敏感值；不得把助手回复或工具输出单独作为用户偏好及纠正反馈的证据。
- F5: 新提取内容与已有记忆重复时必须合并或跳过；与已有记忆冲突时，用户最近一次明确纠正必须生效，并且索引中不得同时保留互相矛盾的有效规则。
- F6: 项目必须提供版本化的人工标注提取数据集。数据集至少包含 120 个对话用例，其中至少 50 个关键偏好正例、30 个其他长期记忆正例和 40 个不应记忆的负例，并覆盖中英文表达、否定表达、纠正、冲突、重复、临时要求、猜测和敏感信息。
- F7: 提取评测必须逐用例比较预测结果与人工标注，计算并输出整体 Precision、Recall、F1，以及关键偏好 Precision、Recall；重复预测不得重复获得 TP。
- F8: 提取评测报告必须列出每个 FP、FN 和错误分类的用例、预测内容、期望内容及匹配证据，使失败可以人工复核。
- F9: 使用 `julycode --new-session` 时，系统不得恢复上一会话的普通消息，但必须在处理首个用户请求前加载同一项目长期记忆和用户长期记忆。
- F10: 空白新会话必须继承项目事实、长期约定、已确认技术决策和关键用户偏好；不得把未完成任务进度或一次性要求当作默认继承内容。
- F11: 项目必须提供至少 20 个版本化跨会话成对评测用例。每个用例包含来源会话、空白新会话首轮任务、必要背景、禁止行为及可观察的正确结果；同一用例必须分别在关闭和开启长期记忆时运行。
- F12: 跨会话评测必须输出首轮任务理解正确率、关闭与开启记忆时的背景重述需求次数及背景重复说明减少率，并列出失败用例证据。
- F13: 普通测试必须使用确定性替身验证提取、指标计算、报告生成、空白新会话注入和成对评测流程，不依赖网络或真实模型。
- F14: 真实模型评测必须作为可显式启动的发布验收运行，记录数据集版本、模型、Provider、时间和各项实际指标；真实模型结果不得被离线替身结果冒充。
- F15: 自动记忆更新或专项评测失败不得破坏现有会话存档、普通聊天、工具调用、权限、上下文压缩和已有记忆文件。

## 非功能需求
- N1: 自动提取优先保证关键偏好精度；对证据不足的内容应选择不记录，而不是猜测长期意图。
- N2: 评测结果必须可复现、可审计；数据集、指标口径和失败明细均保存在项目内，报告不得只给出单一总分。
- N3: 离线专项测试应适合日常开发运行；真实模型评测可以较慢，但必须支持一次命令启动并清楚标识成本和外部依赖。
- N4: 自动记忆仍在一轮自然完成后异步执行，不得明显延迟最终回复展示。
- N5: 新增的来源证据和评测产物不得泄露已过滤的敏感值。
- N6: 新增用户可见信息、报告说明和代码注释使用中文。
- N7: 新增记忆格式必须兼容既有记忆文件；已有合法记忆在升级后仍可被加载和注入。

## 不做的事
- 不引入向量数据库、嵌入模型或语义检索服务。
- 不从用户行为推断隐式偏好。
- 不把未完成任务和最近工作进度作为空白新会话的默认继承内容。
- 不采集真实用户遥测或上传会话数据。
- 不要求普通测试和日常 CI 调用真实模型。
- 不以恢复上一会话历史的方式伪装跨会话记忆继承。
- 不承诺所有模型和所有随机采样都永久达到相同分数；验收结论绑定报告中记录的模型、Provider、数据集版本和运行时间。

## 验收标准
- AC1: 人工标注提取数据集包含不少于 120 个有效用例，且关键偏好正例不少于 50、其他长期记忆正例不少于 30、不应记忆负例不少于 40；数据集校验能拒绝数量不足、重复标识或标签不完整的数据。
- AC2: 指标单元测试覆盖全命中、全部漏提、零预测、重复预测、错误作用域、错误类别和关键偏好误报，计算结果与本规格公式一致。
- AC3: 使用指定真实模型完整运行提取数据集后，整体 F1 不低于 85%，关键偏好 Precision 不低于 98%；关键偏好 Recall 必须单独报告且至少命中 45 个关键偏好正例，防止通过少提取规避精度要求。
- AC4: 对临时要求、模型猜测、仅来自助手或工具的内容以及敏感信息负例运行提取后，不产生对应长期记忆；报告中可查看每条负例结果。
- AC5: 对重复和冲突用例连续执行自动提取后，记忆索引中没有重复或互相矛盾的有效规则，最近一次用户明确纠正生效。
- AC6: 使用 `julycode --new-session` 启动后，会话普通消息数为 0；首个模型请求已包含同一项目的长期记忆和用户长期记忆，但不包含上一会话消息。
- AC7: 至少 20 个跨会话成对用例全部完成真实模型评测，其中至少 18 个在开启记忆的空白新会话中首轮任务理解正确，正确率不低于 90%。
- AC8: 同一组跨会话用例关闭记忆时至少出现一次背景重述需求；开启记忆后的背景重复说明减少率不低于 80%，且报告分别给出两种模式的次数和失败用例。
- AC9: 确定性离线专项测试可一次命令运行并稳定通过，覆盖自动提取链路、指标统计、报告生成、空白新会话和记忆开关对照流程。
- AC10: 真实模型专项评测可一次命令启动，并生成包含数据集版本、模型、Provider、运行时间、整体 Precision/Recall/F1、关键偏好 Precision/Recall、首轮理解正确率、背景重述次数和减少率的报告。
- AC11: 在 tmux 中完成真实端到端场景：第一会话明确一个项目技术决策和一个关键用户偏好，等待自动记忆完成后退出；随后以 `julycode --new-session` 启动，直接下达依赖这些信息的任务；JulyCode 不询问已有背景，并在首轮结果中同时遵循技术决策和关键偏好。
- AC12: 项目现有测试全部通过；自动记忆或专项评测失败时，普通对话仍可继续，既有合法记忆仍能加载。
