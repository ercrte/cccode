# JulyCode Skill 系统 Spec

## 背景
JulyCode 已经具备终端对话、Agent Loop、本地工具、MCP 工具、斜杠命令、结构化系统提示、上下文管理、会话恢复和长期记忆等能力。当前用户如果想让模型执行一套固定的 AI 操作流程，通常需要反复粘贴同样的提示词，也无法把这类流程和它需要的专属工具、工具可见范围、执行模式一起管理。

本阶段要引入本地 Skill 系统，把可复用的 AI 操作封装成独立能力。启动时模型只看到 Skill 的名字和一句说明；当当前任务需要某个 Skill 时，再通过系统级加载能力按需加载完整指令和专属工具。这样可以降低启动上下文成本，提高工具选择准确率，并让 commit、review、test 等高频工作流以统一机制提供。

## 目标
- 用户可以把可复用 AI 操作保存为带元信息的 Markdown Skill，并在项目级、用户级和内置级之间按优先级覆盖。
- JulyCode 启动时只向模型暴露可用 Skill 的名字和一句说明，完整 SOP 指令和专属工具按需加载。
- 已激活 Skill 的完整指令会持续出现在后续模型请求的显眼上下文中，多个 Skill 可以同时激活。
- Skill 可以选择共享当前对话或在独立对话中执行；独立执行完成后把摘要回流到主对话。
- Skill 可以声明模型可见工具白名单，收窄当前工具集合，提升模型选对工具的概率。
- Skill 可以自动形成斜杠短命令，并在 Skill 文件变化后无需重启即可更新。
- 系统内置 commit、review、test 三个样板 Skill，作为常见工作流和 Skill 定义格式示例。

## 功能需求
- F1: 单个 Skill 必须由 YAML frontmatter 和 Markdown 正文组成；frontmatter 保存元信息，Markdown 正文保存发给模型的 SOP 指令。
- F2: Skill frontmatter 必须包含唯一名字、一句话说明、可见工具白名单、执行模式、独立模式历史携带量，并可以包含指定模型。
- F3: Skill 正文必须支持参数占位符；用户通过加载工具或斜杠短命令传入内容后，占位符会被替换为本次执行参数。
- F4: 系统必须支持文件型 Skill 和目录型 Skill；目录型 Skill 必须能把入口 Markdown、专属工具描述和专属工具执行内容作为一个能力包管理。
- F5: 系统必须从项目级、用户级和内置级三个来源发现 Skill；同名 Skill 按项目级高于用户级高于内置级的优先级覆盖。
- F6: 单个 Skill 文件或目录解析失败时，系统必须跳过该 Skill 并记录可见警告，不得阻断其他 Skill 加载或应用启动。
- F7: 优先级覆盖完成后，任意两个仍然可用的 Skill 不得拥有相同名字；无法消解的命名冲突必须给出可定位错误。
- F8: 启动完成后，模型上下文中只能出现可用 Skill 的名字和一句说明，不得提前注入完整 SOP 指令、专属工具实现内容或大段附加材料。
- F9: 系统必须提供一个内置的系统级加载能力，使模型可以按 Skill 名字和本次参数加载完整 SOP 指令及其专属工具。
- F10: 系统级加载能力不得被 Skill 的工具白名单、Plan Mode 的工具收窄或其他普通工具可见性策略隐藏。
- F11: 加载 Skill 成功后，该 Skill 进入激活状态；已激活 Skill 的完整 SOP 指令必须在后续每轮模型请求中持续出现，并且位置比普通会话历史、工具结果摘要和长期记忆更醒目。
- F12: 多个 Skill 可以同时激活；后续模型请求必须能清楚区分每个已激活 Skill 的名字、说明、执行模式、参数和完整 SOP 指令。
- F13: 共享模式 Skill 必须在当前主对话中执行；用户可见请求、模型回复、工具调用和工具结果都保留在主历史中。
- F14: 独立模式 Skill 必须在隔离对话中执行；它可以按 Skill 配置携带指定数量的主历史作为输入，但执行过程中的中间消息不进入主历史。
- F15: 独立模式 Skill 完成后，系统必须把可理解的执行摘要回流到主对话；摘要至少说明输入目标、关键操作、结果、失败或待确认事项。
- F16: 当 Skill 指定模型时，该 Skill 的执行必须使用指定模型；如果指定模型不可用或多个同时执行的 Skill 模型要求冲突，系统必须给出清晰错误并避免静默降级。
- F17: Skill 的可见工具白名单必须在当前基础工具集合上做收窄；Plan Mode、权限系统和安全策略仍然继续生效。
- F18: 多个已激活 Skill 同时声明工具白名单时，系统必须以这些白名单的并集作为 Skill 期望工具集合，再与当前基础工具集合取交集；空白名单表示不暴露普通工具，不得意外扩大可用工具。
- F19: 启动阶段必须校验所有可用 Skill 的工具白名单；白名单中出现不存在的普通工具、MCP 工具或专属工具时，系统必须立即报错并阻止进入可误用状态。
- F20: 目录型 Skill 的专属工具只有在对应 Skill 加载后才暴露给模型；专属工具执行仍必须遵守现有权限、沙箱、脱敏和错误回灌规则。
- F21: 可用 Skill 必须自动注册为斜杠短命令；用户输入对应命令时，系统按该 Skill 的执行模式、参数替换和工具白名单触发执行。
- F22: Skill 斜杠短命令必须参与帮助展示和补全；命令说明使用 Skill 的一句说明，参数提示能表达该 Skill 接受的用户输入。
- F23: Skill 斜杠短命令与已有命令或其他 Skill 命令冲突时，系统必须在启动或热更新时给出清晰冲突信息；内置样板迁移产生的预期同名命令不得保留两套不一致行为。
- F24: Skill 文件新增、修改、删除或优先级变化后，系统必须支持热更新；热更新后新的 Skill 摘要、斜杠命令、完整 SOP 和专属工具可用性应与当前文件状态一致。
- F25: 用户清空当前对话时，系统必须同时清除已激活 Skill；后续模型请求不得继续携带此前激活的完整 Skill 指令。
- F26: 系统必须内置 commit、review、test 三个样板 Skill；它们必须可被启动摘要发现、可被系统级加载能力加载，也可通过斜杠短命令触发。

## 非功能需求
- N1: Skill 摘要注入必须保持轻量，避免因为可用 Skill 数量增加而显著挤占对话上下文。
- N2: Skill 发现、优先级覆盖、解析警告、命令冲突、工具白名单校验和热更新结果必须确定、可测试。
- N3: Skill 加载和执行失败不得导致 TUI 退出、会话状态损坏或后续输入不可用。
- N4: 用户可见说明、警告、错误和样板 Skill 内容必须使用中文。
- N5: Skill 正文、参数和专属工具结果不得绕过现有敏感信息脱敏、权限确认和项目路径边界。
- N6: 共享模式、独立模式和普通对话必须保持清晰边界，避免独立模式中间过程污染主历史。
- N7: Skill 系统不得破坏既有普通聊天、Agent Loop、MCP 工具、Plan Mode、上下文压缩、会话恢复、长期记忆和权限系统行为。

## 不做的事
- 不实现 Skill 市场、远程分发、在线安装或发布流程。
- 不实现 Skill 版本管理、依赖解析或兼容性迁移。
- 不实现跨设备、团队或云端同步 Skill。
- 不实现图形化 Skill 编辑器。
- 不实现运行时从不可信网络地址下载并执行 Skill。
- 不改变 MCP Server 的配置、发现和工具命名规则。
- 不要求 Skill 独立模式保存完整中间历史到主会话。
- 不要求本阶段提供复杂参数表单；参数以用户传入文本和占位符替换为主。

## 验收标准
- AC1: 创建一个包含合法 frontmatter 和 Markdown 正文的 Skill 后，启动摘要中只出现该 Skill 名字和一句说明，不出现完整正文。
- AC2: Skill frontmatter 缺少必填字段、YAML 非法或正文不可读时，该 Skill 被跳过，界面或状态信息能看到对应警告，其他合法 Skill 仍可用。
- AC3: 项目级、用户级和内置级存在同名 Skill 时，系统最终使用项目级版本；删除项目级版本并热更新后，系统回退到用户级或内置级版本。
- AC4: 模型或用户通过系统级加载能力请求某个 Skill 后，后续模型请求包含该 Skill 的完整 SOP 指令和本次参数，且该指令每轮重建都存在。
- AC5: 同时加载两个不同 Skill 后，后续模型请求能同时看到两份完整 SOP，并能区分它们的名字和参数。
- AC6: 共享模式 Skill 执行后，用户请求、模型回复、工具调用和工具结果都保留在主对话历史中。
- AC7: 独立模式 Skill 执行后，主对话历史只增加用户可见触发信息和执行摘要，不增加独立执行过程中的中间工具消息。
- AC8: 独立模式 Skill 配置携带最近 N 条历史时，独立对话只能读取对应数量范围内的主历史；配置为不携带历史时，独立对话不接收主历史内容。
- AC9: Skill 声明指定模型且该模型可用时，本次 Skill 执行使用该模型；指定模型不可用时，界面显示清晰错误且不会静默改用默认模型。
- AC10: Skill 白名单只包含读取和搜索类工具时，该 Skill 激活后的模型请求不暴露写入、编辑或命令执行工具；系统级加载能力仍可用。
- AC11: 多个激活 Skill 的工具白名单不同且无冲突时，模型可见工具为白名单并集与当前基础工具集合的交集，Plan Mode 下仍只暴露只读工具。
- AC12: 任一可用 Skill 的工具白名单引用不存在的工具时，启动或热更新立即失败并指出 Skill 名和工具名。
- AC13: 目录型 Skill 被加载前，它的专属工具不出现在普通模型请求中；加载后，专属工具可以被模型看到并按现有权限规则执行。
- AC14: 输入某个 Skill 对应的斜杠短命令和参数后，系统触发该 Skill，并把参数替换到 SOP 占位符中。
- AC15: `/help` 和 Tab 补全可以展示 Skill 斜杠短命令；命令说明来自 Skill 的一句说明。
- AC16: Skill 斜杠短命令与已有命令冲突时，系统显示冲突来源；对于被迁移为 Skill 的内置样板命令，只保留一套可观察行为。
- AC17: 修改 Skill 的说明、正文、工具白名单或执行模式并热更新后，下一次摘要、加载结果、工具可见性和斜杠命令行为都反映新内容。
- AC18: 删除一个已发现 Skill 并热更新后，该 Skill 不再出现在摘要、帮助和补全中；继续尝试加载它会得到清晰错误。
- AC19: 用户执行清空当前对话后，已激活 Skill 列表为空；后续普通请求不再携带之前激活的完整 SOP 指令。
- AC20: 内置 commit、review、test 三个样板 Skill 在默认安装下可被发现、加载和通过斜杠短命令触发。
- AC21: Skill 加载、独立执行、专属工具失败或权限拒绝时，界面显示可理解错误，输入能力恢复，普通对话仍可继续。
