# MewCode 子 Agent 委派 Spec

## 背景
MewCode 已经具备主对话、Agent Loop、工具系统、权限系统、上下文管理、Hook、MCP 工具和 Skill 独立执行能力。当前主 Agent 执行复杂任务时，所有中间探索、工具结果、权限状态和上下文都混在同一条主对话里；任务一长，主上下文容易被细节污染，主 Agent 也难以并行等待较独立的调研、审查或验证工作完成。

本阶段要提供统一的子 Agent 委派能力。主 Agent 可以把明确的子任务交给独立子 Agent 执行；子 Agent 拥有隔离的运行状态、受限工具集合和独立权限追踪，完成后把结果自动送回主对话。子 Agent 分为定义式和 Fork 式两类：定义式按预定义角色从空白上下文启动，Fork 式继承父对话历史与工具能力以复用已有上下文。

## 目标
- 主 Agent 可以通过稳定的委派入口创建定义式或 Fork 式子 Agent，而不因类型变化改变可见工具列表。
- 用户可以用带 YAML frontmatter 的 Markdown 角色定义文件描述定义式子 Agent，并按多来源优先级覆盖同名角色。
- 定义式子 Agent 可以从空白对话加固定角色提示启动，避免主对话历史污染角色执行。
- Fork 式子 Agent 可以继承父对话历史和工具能力，并默认在后台运行，降低重复上下文传入成本。
- 子 Agent 的消息、权限、文件读取缓存、Token 计数和运行结果必须与主 Agent 及其他子 Agent 隔离。
- 子 Agent 可以共享已有基础设施，例如模型访问能力、Hook 能力和同一项目文件系统视图。
- 子 Agent 以非交互方式持续运行到完成、失败、取消或达到限制；运行过程不要求用户在子 Agent 内继续对话。
- 后台任务管理必须追踪子 Agent 状态、结果和用量，并在任务完成后自动向主对话追加用户可见的完成通知。
- 子 Agent 工具可见性必须受到多层限制，防止越权工具调用和无限嵌套。

## 功能需求
- F1: 系统必须向主 Agent 暴露一个稳定的 Agent 委派入口；定义式和 Fork 式委派必须通过同一个入口用类型参数区分，不能因为选择不同委派类型而改变主 Agent 可见工具列表。
- F2: Agent 委派入口必须能接收子任务说明、委派类型、可选角色名、可选后台偏好和必要的运行约束；缺少对应类型必需信息时必须返回可理解的失败结果。
- F3: 定义式子 Agent 的角色必须由带 YAML frontmatter 的 Markdown 文件定义；frontmatter 至少包含角色名、用途说明、工具白名单、工具黑名单、模型偏好、最大轮次和权限模式。
- F4: 角色模型偏好必须支持继承当前默认模型，也必须支持选择系统声明支持的模型档位，例如 haiku、sonnet 或 opus。
- F5: Markdown 正文必须作为子 Agent 生命周期内持续生效的系统提示，用于定义该角色的身份、职责和工作风格。
- F6: 系统必须从插件级、内置级、用户级和项目级多个来源加载角色定义；同名角色按项目级高于用户级、用户级高于内置级、内置级高于插件级的优先级覆盖。
- F7: 角色定义解析失败、缺少必填元信息或引用不可用工具时，系统必须给出可定位的配置错误或警告，不得进入可能误用的半可用状态。
- F8: 定义式委派必须使用空白对话启动，只携带角色提示、子任务说明和必要的运行环境信息；默认不得携带父对话历史。
- F9: Fork 式委派必须继承父对话当前可见历史、当前可见工具能力和相关运行约束，使首次请求可以复用父上下文中的已有信息。
- F10: Fork 式委派必须强制进入后台运行；即使主 Agent 请求前台执行，系统也必须改为后台并在结果中说明该行为。
- F11: 子 Agent 必须拥有独立消息历史；子 Agent 的中间模型回复、工具调用和工具结果不得直接写入主对话历史。
- F12: 子 Agent 必须拥有独立权限追踪；它的临时允许、拒绝、等待确认状态和权限统计不得污染主 Agent 或其他子 Agent。
- F13: 子 Agent 必须拥有独立文件读取缓存和 Token 计数；一个子 Agent 的缓存命中、外置工具结果和用量估算不得影响其他运行上下文的判断。
- F14: 子 Agent 可以共享模型访问能力、Hook 能力和项目文件系统视图；共享基础设施不得破坏 F11 到 F13 的状态隔离。
- F15: 子 Agent 必须以非交互“跑到底”模式执行；只要未触发停止条件且模型继续请求工具，系统必须继续循环执行，直到模型不再请求工具或达到限制。
- F16: 子 Agent 停止条件至少包括正常完成、达到最大轮次、工具或模型错误、权限无法继续、取消和系统限制拒绝。
- F17: 子 Agent 完成或停止时，系统必须生成结构化结果；结果至少包含任务目标、执行摘要、完成状态、停止原因、关键输出、错误信息和用量信息。
- F18: 后台子 Agent 完成后，系统必须自动向主对话追加一条用户可见的完成通知；通知必须包含任务标识、完成状态、摘要、停止原因和关键结果，使主 Agent 后续请求也能看到该结果。
- F19: 后台任务管理必须能追踪每个子 Agent 的任务标识、委派类型、角色、状态、启动时间、结束时间、结果、错误和用量。
- F20: 系统必须支持三种进入后台的方式：主 Agent 显式指定后台、前台执行超过阈值后自动转入后台、用户在任务运行中手动切入后台。
- F21: 前台子 Agent 未转后台时，主 Agent 必须等待其结果并把结构化结果作为委派入口的工具结果返回；转后台后，委派入口必须立即返回后台任务已启动或已切换的结果。
- F22: 全局禁止的工具不得暴露给任何子 Agent，也不得被角色白名单、Fork 继承或后台运行策略重新启用。
- F23: 定义式子 Agent 的工具集合必须同时受到角色白名单、角色黑名单、当前运行模式、权限策略和后台安全策略限制。
- F24: Fork 式子 Agent 的工具集合必须从父 Agent 当前可见工具能力继承，并继续受到全局禁止、后台安全策略和防嵌套策略限制。
- F25: 后台子 Agent 必须受到后台工具白名单限制；不适合后台自动执行的交互式确认、无限等待或高风险工具不得在后台执行。
- F26: 子 Agent 默认不得再调用 Agent 委派入口创建新的子 Agent；如未来允许嵌套，也必须有显式深度限制。本阶段必须防止无限嵌套。
- F27: 当子 Agent 请求不可用、被限制或被权限拒绝的工具时，系统必须把结构化失败结果回灌给子 Agent；只有达到明确停止条件时才结束子 Agent。
- F28: 子 Agent 运行状态变化必须能被主对话或界面观察到，至少覆盖已启动、进入后台、运行中、完成、失败、取消和结果已通知。
- F29: 用户取消主任务时，系统必须有明确策略处理其派生的子 Agent；仍在前台等待的子 Agent 必须停止，已进入后台的子 Agent 必须保留状态并在完成后按后台规则通知。

## 非功能需求
- N1: 委派入口的工具描述必须稳定，避免因角色数量、委派类型或后台状态变化导致主 Agent 工具列表频繁变化。
- N2: 子 Agent 状态隔离必须可测试、可观察，不能依赖提示词约束来保证历史、权限或用量不互相污染。
- N3: 默认安全策略必须保守；当无法确认某工具是否适合子 Agent 或后台执行时，系统必须拒绝或转为可理解的失败结果，而不是静默执行。
- N4: 子 Agent 运行失败、角色配置错误、后台通知失败或结果生成失败不得导致主 TUI 退出、主会话损坏或后续输入不可用。
- N5: 用户可见提示、错误、状态和结果通知必须使用中文，并延续现有敏感信息脱敏要求。
- N6: 定义式与 Fork 式委派在不同模型供应商下必须保持一致的用户可见语义；供应商差异不得泄漏到主 Agent 或界面交互层。
- N7: Fork 式继承父历史的行为必须避免复制未完成工具调用或破坏当前主 Agent 循环状态。
- N8: 后台任务结果进入主对话时必须简洁可读；不得把子 Agent 的完整中间历史自动灌入主上下文。

## 不做的事
- 不实现 Worktree、临时目录、容器或操作系统级文件隔离；本阶段子 Agent 与主 Agent 看到同一项目文件系统视图。
- 不实现多 Agent 团队编排、角色间协商、投票、队列调度策略或任务依赖图。
- 不实现后台任务跨会话持久化；应用重启后不要求恢复未完成子 Agent 或历史后台结果。
- 不实现子 Agent 内的交互式多轮用户对话；子 Agent 运行期间不要求用户向它直接输入。
- 不实现远程角色市场、在线安装或角色版本依赖管理。
- 不允许子 Agent 绕过现有权限、沙箱、上下文管理、Hook 和工具安全策略。
- 不把子 Agent 完整中间消息自动写入主会话，也不要求主对话能逐条回放子 Agent 内部思考和工具过程。

## 验收标准
- AC1: 主 Agent 请求定义式委派时，系统通过同一个委派入口创建子 Agent，并且主 Agent 可见工具列表不因委派类型发生变化。
- AC2: 主 Agent 请求 Fork 式委派时，系统仍使用同一个委派入口，且该任务被强制作为后台任务启动。
- AC3: 合法的 Markdown 角色定义被加载后，定义式委派可以按 YAML frontmatter 中的角色名启动，并在执行期间持续遵循正文描述的职责和工作风格。
- AC4: 项目级、用户级、内置级和插件级存在同名角色时，最终生效角色符合项目级高于用户级、高于内置级、高于插件级的覆盖顺序。
- AC5: 角色定义缺少必填 frontmatter 字段、YAML 格式非法或引用不可用工具时，系统给出可定位错误或警告，并避免启动错误角色。
- AC6: 定义式子 Agent 启动后看不到父对话历史中的无关消息；它只能基于角色提示、子任务说明和必要环境信息工作。
- AC7: Fork 式子 Agent 启动后能引用父对话当前已有上下文，并继承父 Agent 当前可见工具能力中允许继承的部分。
- AC8: 子 Agent 的中间模型消息、工具调用和工具结果不会直接出现在主对话历史中；主对话只收到委派入口返回结果或后台完成通知。
- AC9: 子 Agent 的临时权限允许或拒绝不会改变主 Agent 后续同类工具调用的权限判断。
- AC10: 子 Agent 的文件读取缓存、外置工具结果和 Token 计数不会改变主 Agent 或其他子 Agent 的上下文估算和缓存状态。
- AC11: 子 Agent 可以使用共享模型访问能力、Hook 能力和项目文件系统视图完成任务，且这些共享能力不破坏状态隔离。
- AC12: 子 Agent 在模型连续请求工具时会持续运行；当模型给出无工具调用的最终回复时，子 Agent 正常完成并生成结构化结果。
- AC13: 子 Agent 达到最大轮次、遇到模型错误、工具错误、权限无法继续或取消时，会停止并生成包含停止原因的结构化结果。
- AC14: 前台定义式子 Agent 完成后，主 Agent 收到包含任务目标、摘要、状态、停止原因、关键输出和用量的工具结果。
- AC15: 后台子 Agent 完成后，主对话自动出现一条用户可见完成通知，通知包含任务标识、完成状态、摘要、停止原因和关键结果。
- AC16: 后台任务管理能展示或返回每个子 Agent 的任务标识、类型、角色、状态、结果、错误和用量。
- AC17: 主 Agent 显式指定后台时，委派入口立即返回后台任务已启动信息，任务完成后按后台通知规则回到主对话。
- AC18: 前台子 Agent 超过阈值后自动切入后台，主 Agent 收到已转后台信息，任务完成后自动通知主对话。
- AC19: 用户在子 Agent 运行中手动切入后台后，主 Agent 不再阻塞等待该任务，任务完成后自动通知主对话。
- AC20: 全局禁止工具不会出现在任何子 Agent 可用工具集合中，也不能通过角色白名单或 Fork 继承启用。
- AC21: 定义式子 Agent 的工具集合同时符合角色白名单、角色黑名单、当前运行模式、权限策略和后台安全策略。
- AC22: Fork 式子 Agent 的工具集合不会超过父 Agent 当前可见工具能力，并继续受到全局禁止、后台安全策略和防嵌套策略限制。
- AC23: 后台子 Agent 请求不适合后台执行的工具时，系统不执行该工具，并把结构化失败结果回灌给子 Agent。
- AC24: 子 Agent 尝试再次调用 Agent 委派入口时，系统拒绝该调用并返回防嵌套失败结果。
- AC25: 用户取消正在等待的主任务时，前台子 Agent 被停止；已后台化的子 Agent 保留后台状态并在完成后通知主对话。
- AC26: 在端到端场景中，用户要求主 Agent 委派一个代码搜索或审查子任务后，主 Agent 能启动子 Agent、继续保持主上下文简洁，并在子 Agent 完成后看到自动回流的结果。
