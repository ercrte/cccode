# JulyCode Agent Loop Spec

## 背景
JulyCode 已经具备全屏对话、流式回复、多轮上下文，以及第一版本地工具系统。上一阶段打通了“模型请求一次工具、系统执行、结果回灌、模型生成最终回复”的链路，但每次用户请求最多只能完成一轮工具调用；如果任务需要连续读取、搜索、修改和验证，用户必须反复催促模型继续。

本阶段要把一次工具链路升级为 Agent Loop。JulyCode 应能围绕同一个用户目标反复让模型判断下一步、调用工具、观察结果并调整行动，直到模型给出最终回复或触发明确停止条件。同时，Agent 的运行过程要通过统一事件流暴露给界面，避免界面直接理解循环细节或供应商原始流事件。

## 目标
- JulyCode 可以在一次用户请求中自主执行多轮“思考、调用工具、观察结果、继续调整”的工作流。
- JulyCode 可以用清晰、可观测的条件停止 Agent Loop，避免无限循环或失控执行。
- JulyCode 可以把模型流式文本、工具调用、工具结果、Token 用量和进度状态统一作为事件输出给界面。
- JulyCode 可以实时展示模型文本增量，同时保留完整模型响应用于判断下一步行动。
- JulyCode 可以在一次模型响应包含多个工具调用时，按工具安全性分批执行：能并发的并发执行，有副作用的保持顺序执行。
- JulyCode 可以支持两段式 Plan Mode：`/plan <需求>` 只允许读类工具产出并保存待执行计划，`/do` 使用全工具执行已保存计划。

## 功能需求
- F1: 用户提交普通任务后，JulyCode 必须启动 Agent Loop，并在同一个任务内反复执行“请求模型、接收模型输出、执行模型请求的工具、回灌工具结果”的循环，直到满足停止条件。
- F2: 当模型完成回复且没有请求新的工具时，JulyCode 必须把该回复作为任务最终结果展示给用户，并正常结束本次 Agent Loop。
- F3: JulyCode 必须设置每个任务的最大循环轮次；达到上限时必须停止继续请求模型或执行工具，并向用户说明任务因迭代上限停止。
- F4: 用户必须能取消正在运行的 Agent Loop；取消后 JulyCode 必须停止后续模型请求和工具调度，恢复输入能力，并把取消状态展示给用户。
- F5: 当模型连续两轮请求不存在的工具时，JulyCode 必须停止本次 Agent Loop，并向用户说明停止原因；第一次未知工具调用必须以失败结果回灌给模型，让模型有一次自我修正机会。
- F6: 当模型流式输出或供应商请求发生错误时，JulyCode 必须停止本次 Agent Loop，展示脱敏后的错误信息，并恢复用户继续输入的能力。
- F7: Agent Loop 必须通过统一事件流向界面输出运行状态，事件至少覆盖文本增量、工具调用开始、工具执行结果、Token 用量、循环进度、最终完成、取消和错误。
- F8: 界面必须只消费 Agent Loop 的统一事件，不直接依赖 OpenAI、Anthropic 或其他供应商的原始流式事件。
- F9: 流式收集必须走双路：一边把可展示文本增量实时推给界面，一边累计完整模型回复；完整回复必须用于会话追加、工具调用判断和循环停止判断。
- F10: 当模型一次返回多个工具调用时，JulyCode 必须全部纳入同一轮处理，不能只执行第一个工具调用。
- F11: 多工具调用必须按安全性分批执行：无副作用、可并发的工具可以并发执行；可能改变文件、执行命令或产生外部影响的工具必须按模型给出的顺序串行执行。
- F12: 多工具调用的结果必须全部回灌给模型，且回灌顺序必须与模型原始工具调用顺序一致，便于模型正确关联观察结果。
- F13: 如果同一轮工具调用中既有可并发工具又有有副作用工具，JulyCode 必须保证有副作用工具不会被提前越过其前面的调用，也不会与可能影响其输入或输出的调用并行执行。
- F14: `/plan <需求>` 必须启动规划阶段。规划阶段只允许读取、查找、搜索等读类工具，禁止写文件、改文件、执行命令或其他有副作用工具。
- F15: 规划阶段结束时，JulyCode 必须向用户展示模型产出的计划，并把该计划保存为当前待执行计划；规划阶段不得执行计划中的修改或命令动作。
- F16: `/do` 必须执行当前待执行计划。执行阶段必须切回全工具能力，并围绕保存的计划启动 Agent Loop，直到完成或触发停止条件。
- F17: 当不存在待执行计划时，用户输入 `/do` 必须得到清晰提示，不能启动空执行。
- F18: 当新的 `/plan <需求>` 成功生成计划时，JulyCode 必须用新计划替换旧的待执行计划；当 `/do` 成功执行完成后，待执行计划必须被清除。
- F19: Agent Loop 中的工具失败结果必须回灌给模型，允许模型根据失败原因调整下一步；只有达到明确停止条件时才终止整个任务。
- F20: Agent Loop 必须保留当前运行期会话上下文，使同一次任务内的模型输出、工具调用和工具结果能被后续轮次引用。

## 非功能需求
- N1: Agent Loop 的行为必须对 OpenAI 和 Anthropic 两类模型协议保持一致；供应商差异不得泄漏到界面交互层。
- N2: 迭代上限、取消、未知工具停止和流式错误都必须以可观测事件体现，便于界面、测试和未来前端复用。
- N3: 未触发工具调用的普通聊天仍必须保持流式显示体验，不应因引入 Agent Loop 变成等待完整回复后再展示。
- N4: 工具执行失败、模型请求失败或用户取消不得导致 TUI 退出、会话状态损坏或后续输入不可用。
- N5: 错误信息和工具结果必须延续现有脱敏要求，不得泄露完整密钥。
- N6: 并发执行只用于系统判定为无副作用的工具；无法确认安全性的工具必须按有副作用工具处理。
- N7: Token 用量事件在供应商提供用量信息时必须传递给界面；供应商未提供用量信息时，系统不得因此中断任务。
- N8: 本阶段实现范围必须聚焦 Agent Loop、事件流、多工具调度和 Plan Mode，不引入权限确认、上下文压缩或交互式确认系统。

## 不做的事
- 不实现权限系统、危险操作确认、用户逐步批准工具调用或命令白名单。
- 不实现上下文压缩、长期记忆、跨启动任务恢复或跨启动计划持久化。
- 不实现用户交互式确认计划步骤；`/do` 即表示执行当前待执行计划。
- 不实现外部插件系统、第三方工具市场或动态加载工具。
- 不实现长期后台任务、交互式命令会话或可持续输入的命令进程。
- 不要求模型在计划阶段输出固定模板；只要求计划内容清晰可展示、可作为后续执行目标。
- 不改变现有工具的业务能力边界；本阶段只改变工具调用的循环、调度和展示方式。

## 验收标准
- AC1: 用户提交需要多步完成的任务时，JulyCode 能在一次请求内连续调用多个工具并最终回复完成结果。
- AC2: 当模型回复不包含工具调用时，JulyCode 结束 Agent Loop，并把该回复作为最终回复展示。
- AC3: 当任务达到最大循环轮次时，JulyCode 停止继续执行，界面显示迭代上限停止原因，输入区恢复可用。
- AC4: 用户取消运行中的任务后，JulyCode 不再发起后续模型请求或工具调度，界面显示已取消，输入区恢复可用。
- AC5: 模型第一次请求未知工具时，JulyCode 将未知工具失败结果回灌给模型；如果下一轮仍请求未知工具，JulyCode 停止并说明连续未知工具导致停止。
- AC6: 模型流式输出或供应商请求出错时，JulyCode 停止本次任务，展示脱敏错误，输入区恢复可用。
- AC7: Agent Loop 运行期间，界面能观察到文本增量、工具开始、工具结果、Token 用量或未知用量状态、循环进度和最终完成事件。
- AC8: 未触发工具调用的普通聊天仍能实时显示文本增量，并保留当前运行期多轮上下文。
- AC9: 当模型一次返回多个读类工具调用时，JulyCode 能并发执行这些工具，并把所有结果回灌给模型。
- AC10: 当模型一次返回多个有副作用工具调用时，JulyCode 按模型给出的顺序串行执行，并把所有结果按原顺序回灌。
- AC11: 当同一轮同时包含读类工具和有副作用工具时，JulyCode 的执行顺序不会让有副作用工具越过其前面的调用，也不会让依赖关系不明的调用并行执行。
- AC12: 工具失败后，如果未触发停止条件，JulyCode 能把失败结果回灌给模型，并允许模型继续调整行动。
- AC13: 用户输入 `/plan <需求>` 后，JulyCode 只允许读类工具参与规划，最终展示计划并保存为待执行计划。
- AC14: `/plan <需求>` 期间模型尝试调用写入、修改、命令执行或其他有副作用工具时，JulyCode 不执行该工具，并把受限失败结果反馈给模型。
- AC15: 用户输入 `/do` 且存在待执行计划时，JulyCode 使用全工具能力执行该计划，并在完成后清除待执行计划。
- AC16: 用户输入 `/do` 但不存在待执行计划时，JulyCode 展示清晰提示，不启动空执行。
- AC17: 用户连续生成两个计划时，第二个计划替换第一个待执行计划，后续 `/do` 执行的是最新计划。
- AC18: Agent Loop 事件流可被自动化测试直接消费，以验证循环进度、工具调度、停止条件和 Plan Mode 行为，而无需启动真实 TUI。
