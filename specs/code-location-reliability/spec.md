# 代码定位工具可靠性 Spec

## 背景

JulyCode 已提供文件查找、代码搜索、文件读取和命令执行能力，并在模型提示中要求优先使用专用工具完成代码定位。但真实会话记录显示，模型仍频繁通过命令工具执行 `grep`、`find`、`sed`、`cat` 等定位和读取操作。

已确认主要原因不是专用工具未暴露，而是其可靠性和能力不足：当环境缺少高效搜索程序时，全项目搜索可能扫描体积很大的 JulyCode 运行数据并超时；搜索单个文件时可能无法正确解析结果；文件读取不能指定局部范围，读取大文件后模型会转而使用命令工具查看特定行。

本阶段改进现有专用工具，使其能够稳定承担代码定位和局部读取任务，同时保持现有工具名称和安全边界不变。

## 目标

- 全项目文件查找和代码搜索不被 JulyCode 运行数据、版本控制元数据、缓存或构建产物拖慢。
- 无论运行环境是否提供高效搜索程序，代码搜索都能在相同范围内返回一致、可理解的结果。
- 目录搜索和单文件搜索都能正确返回文件路径、位置和匹配文本。
- 文件读取支持局部范围，模型无需通过命令工具查看文件中的指定行。
- 模型在只读代码定位场景中优先使用专用工具，命令工具主要用于构建、测试、检查或用户明确要求的命令。
- 通过回归测试和真实终端对话验证工具选择及执行结果。

## 功能需求

- F1: 代码搜索必须同时支持全项目、指定目录和指定单个文件三种范围，并为每条命中返回正确的项目相对路径、行号、列号和匹配文本。
- F2: 在 Git 项目中，未显式指定目标的全项目文件查找和代码搜索必须应用当前 Worktree 的有效忽略规则，排除已忽略内容，同时保留未跟踪但未忽略的项目文件。
- F3: 在非 Git 项目中，未显式指定目标的全项目文件查找和代码搜索必须默认排除版本控制元数据、JulyCode 运行数据、虚拟环境、依赖目录、测试缓存、语言缓存和常见构建产物。
- F4: 当调用方显式指定项目内文件或目录时，专用工具必须以该目标为搜索范围；默认忽略规则不得阻止对该显式目标的合法访问。
- F5: 当高效搜索程序可用时，代码搜索应使用其完成搜索；当其不可用、启动失败或执行超时时，系统必须使用内置搜索能力继续完成请求，并保持相同的范围和忽略语义。
- F6: 文件查找和代码搜索必须遵守最大结果数限制；达到限制后应停止继续收集结果，不得在已经得到足够结果后仍完整遍历大型目录。
- F7: 文件读取必须支持调用方指定局部文本范围，并返回该范围的内容以及足以判断实际读取位置、文件总规模和是否仍有后续内容的信息。
- F8: 未指定局部范围时，文件读取必须保持现有整文件读取和输出截断行为；非法范围必须返回可理解的参数错误，不得读取错误位置或导致应用异常。
- F9: 专用工具在没有匹配结果时必须返回成功且结果为空；搜索程序不可用、单个文件没有命中或被排除目录中存在命中都不得被误报为工具异常。
- F10: 模型工具使用说明必须明确要求只读文件定位、代码搜索和局部查看优先使用专用工具；只有专用工具无法表达任务、用户明确要求命令或进入构建测试阶段时，才使用命令工具。
- F11: 自动评测必须能够区分“使用专用工具完成只读定位”和“通过命令工具绕过专用工具”，并覆盖全项目搜索、单文件搜索、缺少高效搜索程序、忽略目录和局部读取场景。

## 非功能需求

- N1: 全项目搜索不得遍历被默认排除的 JulyCode 运行数据或版本控制元数据；这些目录体积增长不应导致正常源码搜索超时。
- N2: 专用搜索在当前工具超时保护内必须可完成合理规模项目的常见代码定位请求；失败时必须返回稳定、可理解的错误类型。
- N3: 文件查找、代码搜索和文件读取必须保持现有项目路径沙箱与权限语义，不得通过显式目标访问项目目录之外的内容。
- N4: 工具结果结构的既有字段应保持兼容；新增能力不得破坏现有模型供应商适配、Agent Loop、权限系统、仓库地图或子 Agent 调用。
- N5: 实现必须有单元测试、集成回归测试和 tmux 真实对话验收，且现有相关测试集保持通过。

## 不做的事

- 不新增 `grep`、`glob` 或其他工具别名。
- 不重命名现有核心工具。
- 不增加任意 Shell 管道、重定向、`cd` 或复合命令支持。
- 不把命令工具改造成交互式 Shell 或 PTY。
- 不改变工具权限等级、危险命令规则或项目路径沙箱。
- 不增加二进制文件内容搜索、语义搜索、语言服务器索引或模糊符号解析。
- 不修改仓库地图的候选文件与忽略规则。

## 验收标准

- AC1: 在没有高效搜索程序的环境中，对包含大型 JulyCode 运行目录的项目执行全项目代码搜索，能够在现有超时保护内找到源码命中，且不会读取运行目录中的文件。（覆盖 F2、F3、F5、F6、N1、N2）
- AC2: Git 项目的全项目搜索会排除已忽略文件，包含未跟踪但未忽略文件；显式指定项目内被忽略文件或目录时仍能搜索该目标。（覆盖 F2、F4）
- AC3: 非 Git 项目的全项目文件查找和代码搜索会排除规定的元数据、运行数据、缓存、依赖和构建目录。（覆盖 F3）
- AC4: 对指定单个文件执行代码搜索时，命中结果包含正确的相对路径、行号、列号和文本；无命中时成功返回空结果。（覆盖 F1、F9）
- AC5: 文件查找和代码搜索达到最大结果数后只返回规定数量，并停止继续收集候选结果。（覆盖 F6）
- AC6: 指定合法局部范围读取文件时，只返回对应内容，并能观察实际范围、文件总规模和是否有后续内容；非法范围返回参数错误。（覆盖 F7、F8）
- AC7: 未指定局部范围读取文件时，现有整文件读取、缓存使用和输出截断行为保持兼容。（覆盖 F8、N4）
- AC8: 高效搜索程序不可用、启动失败或执行超时时，内置搜索仍遵守相同范围和忽略规则，并返回一致的命中结构。（覆盖 F5、F9）
- AC9: 只读代码定位评测要求使用文件查找、代码搜索或文件读取工具，并能在不需要命令的场景中识别命令工具绕过行为。（覆盖 F10、F11）
- AC10: 现有工具、权限、Agent、供应商适配和 TUI 相关测试保持通过，项目目录之外的路径仍被拒绝。（覆盖 N3、N4、N5）
- AC11: 在 tmux 中向 JulyCode 提交真实的代码定位请求时，可以观察到模型使用专用工具完成搜索与局部读取，最终回复引用正确源码位置，输入区恢复可用。（覆盖 F10、F11、N5）
- AC12: 模型可见工具集合仍保持现有核心工具名称，不出现 `grep` 或 `glob` 别名。（覆盖“不做的事”）
