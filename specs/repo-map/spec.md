# MewCode Repo Map Spec

## 背景
MewCode 已具备结构化系统提示、上下文预算管理、代码读取与搜索工具、Agent Loop，以及 OpenAI 和 Anthropic 的 Prompt Cache 支持。模型目前需要先依靠文件查找和代码搜索逐步认识仓库；当用户没有给出准确路径或符号名时，模型缺少一份低成本的全局代码结构视图，可能增加探索轮次，也更容易遗漏真正相关的文件。

本阶段为 MewCode 增加 Repo Map。系统在 Python 项目中自动生成一份受 Token 预算约束的仓库地图，向模型提供重要文件、关键符号及启发式代码关系的压缩视图。地图用于帮助模型决定下一步应该读取或搜索哪些文件，不替代真实源码，也不改变现有工具调用和权限流程。

Repo Map 是随仓库工作区版本和当前请求变化的临时上下文。OpenAI Prompt Cache 要求可复用内容形成精确相同的前缀，并允许部分较新模型使用显式缓存断点；Anthropic 按 `tools → system → messages` 的顺序组成缓存前缀，并允许多个断点覆盖不同变化频率的内容。因此 Repo Map 不得进入长期稳定缓存前缀的身份，但同一份 Repo Map 快照可以在 Provider 明确支持时使用独立的快照级缓存边界。

参考：
- [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)
- [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 关键语义
- **项目根目录：** MewCode 启动目录位于 Git Worktree 内时，使用包含该目录的 Worktree 根目录；否则使用启动目录。Repo Map 不得越出该根目录。
- **仓库工作区版本：** 由项目身份、当前分支或 Worktree 身份、符合条件的文件集合及其内容指纹共同确定。内容指纹必须基于文件内容，不能只依赖修改时间。
- **Repo Map 快照：** 由仓库工作区版本、当前请求提示、有效地图预算和地图生成规则共同确定。同一组输入必须得到语义和字节内容一致的快照。
- **请求期临时上下文：** Repo Map 的来源是 MewCode 生成的仓库索引，信任级别是不可信仓库数据，生命周期只覆盖当前请求链路，缓存范围最多为同一快照。
- **长期稳定缓存前缀：** Repo Map 出现之前，由既有工具定义、稳定提示和可缓存运行时块序列化形成的 Provider 请求前缀。
- **有效地图预算：** `min(用户配置的地图预算, 上下文管理器为本次请求授予的地图预算)`。预算使用 MewCode 现有上下文 Token 估算规则计算。

## 目标
- 在 Python 项目中默认自动向主 Agent 提供仓库级代码结构视图。
- 让与当前请求更相关、在仓库中更重要的文件和符号优先进入有限的上下文预算。
- 在 Agent Loop 修改源码后及时刷新地图，避免后续模型迭代看到已删除符号或旧签名。
- 减少模型为定位入口、定义和关联文件而执行的不必要探索调用。
- 保持地图内容确定、可解释，并能正确隔离不同仓库、分支和 Worktree。
- 保持长期稳定 Prompt Cache 前缀、工具调用、上下文压缩、会话持久化和 Provider 行为不回归。
- 为后续增加其他编程语言保留扩展空间，但首版只交付 Python 仓库能力。

## 功能需求
- F1: 当项目中存在可分析的 `.py` 或 `.pyi` 文件时，Repo Map 必须默认自动启用；用户可以通过项目配置或用户配置显式关闭。
- F2: Git 项目必须以当前 Worktree 根目录为地图范围，并应用 Git 的有效忽略规则；未跟踪但未被忽略的 `.py` 和 `.pyi` 文件必须包含在候选集合中。非 Git 项目必须以启动目录为范围，并默认排除 `.git`、`.mewcode`、`__pycache__`、`.venv`、`venv`、`build`、`dist`、`.tox`、`.pytest_cache`、`.mypy_cache` 和 `node_modules`。
- F3: Repo Map 不得跟随目录或文件符号链接；任何解析后位于项目根目录之外的路径必须被排除。所有输出路径必须使用相对于项目根目录的 POSIX 路径表示。
- F4: Repo Map 必须为入选文件提供相对路径和关键代码结构，至少能够表示模块中的类、函数、异步函数、类方法及其可见签名，并支持 Python 源文件声明的合法文本编码。
- F5: Repo Map 首版必须识别以下可确定关系：`import package.module`、`from package.module import Symbol`、相对导入、`as` 别名、同模块直接名称引用，以及唯一可解析定义对应的调用引用。
- F6: `obj.method()` 的实例类型推断、`getattr`、字符串导入、`import *`、动态 re-export 和无法消歧的同名符号不得被描述为精确调用关系。启发式或歧义关系必须降权或忽略，地图整体必须明确标识其关系只用于导航，不是精确调用图。
- F7: 地图排序必须优先考虑当前用户请求中明确出现的文件路径、模块名和符号名，再考虑仓库内启发式关系的重要程度。所有候选必须先按稳定路径顺序汇总，最终排序键必须等价于 `(-round(score, 8), relative_posix_path, qualified_name, line_number)`；空关系图、同分、重复符号和无可解析关系时仍须按该稳定后备顺序产生结果。
- F8: Repo Map 的配置预算默认为 2,000 Token。地图预算必须使用 MewCode 现有上下文 Token 估算器，对完整渲染块进行估算；标题、不可信数据提示、边界标记、文件路径、导航提示和裁剪标记都必须计入预算。
- F9: 上下文分配优先级必须是：不可省略的系统与工具协议、当前用户请求、必要工具结果、用户明确读取的源码、必须保留的近期对话，最后才是 Repo Map。有效地图预算不足时必须先缩小或省略 Repo Map，不得为了保留地图而删除更高优先级内容。
- F10: 文件条目、顶层符号签名和类作用域必须按完整原子单元渲染，不得输出半行或半个条目。方法入选时必须同时保留所属类；单个签名仍超过预算时，应降级为保留符号种类、限定名和省略参数的合法短签名。若连边界提示与一个最小完整文件符号条目都无法放入有效预算，必须整体省略 Repo Map。
- F11: 同一仓库工作区版本、请求提示、有效预算和地图生成规则下，Agent Loop 的多次模型调用必须复用字节一致的 Repo Map 快照。已知只读操作不得改变仓库工作区版本。
- F12: 成功执行明确修改、创建或删除源码文件的工具后，必须使对应文件的旧分析结果失效并更新仓库工作区版本；后续模型迭代必须取得新版本对应的 Repo Map。执行任意命令或无法准确判断写入范围的副作用工具后，必须比较执行前后的候选文件集合与内容指纹；无法确定影响范围时必须使整个仓库图和快照失效。
- F13: 源码被修改但修改时间未变化时仍必须产生新的内容指纹和仓库工作区版本。源码变化、新建、删除、分支切换和 Worktree 切换后，不得返回旧版本地图，也不得跨项目错误复用缓存结果。
- F14: 未变化文件的分析结果可以复用，但缓存身份必须至少覆盖项目身份、相对路径、内容指纹和解析规则版本；仓库关系图身份必须覆盖有序文件指纹集合；最终快照身份必须覆盖仓库工作区版本、请求提示、有效预算和渲染规则版本。
- F15: Repo Map 必须位于长期稳定缓存前缀之后，不参与长期稳定前缀的摘要、缓存分组身份或路由身份。无论 Repo Map 是否启用、内容如何变化，Provider 序列化结果中从请求开头到长期稳定缓存边界的字节序列必须保持不变。
- F16: 当 Prompt Cache 已开启且 Provider adapter 明确声明支持独立内容块缓存边界时，必须对同一 Repo Map 快照设置短期、内容精确匹配的次级缓存边界；Repo Map 变化只能使该快照级缓存失效，不能使更早的长期稳定前缀失效。不支持显式断点的模型必须继续使用其兼容的自动缓存行为，不得发送不受支持的缓存参数。
- F17: Repo Map 的内部语义必须始终保留“生成式上下文、不可信仓库数据、请求期临时生命周期、快照级缓存范围”。Provider adapter 可以根据 API 约束选择合法的 system、developer 或合成消息表示，但不得把 Repo Map 伪装成用户原始输入。
- F18: Repo Map 不得写入聊天消息历史、上下文摘要、会话持久化数据、会话恢复数据、长期记忆、用户输入记录或助手输出记录。每次请求只根据当前有效快照临时组装，结束后不得作为普通消息遗留。
- F19: Repo Map 占用必须进入现有请求上下文规模估算。缩小或省略地图后仍超过整体上下文预算时，继续沿用现有上下文压缩和超限处理，不得绕过其安全余量。
- F20: 项目无可分析 Python 文件、功能关闭、初次索引未及时完成、单文件语法错误、编码错误、读取失败或部分关系构建失败时，MewCode 必须安全降级。错误文件不能导致整份地图不可用；组装模型请求时初次索引尚未就绪，应立即固定省略本轮地图，不得为等待索引而延迟模型请求，也不得在仓库版本不变时中途替换快照。
- F21: Repo Map 内容必须作为不可信数据处理：不输出 docstring、注释或 decorator；默认值统一渲染为 `...`；字符串形式的注解内容不得原样输出；控制字符必须清理；单行最长 160 个字符；地图必须由明确边界包裹，并提示模型它只用于导航，修改或依赖实现细节前仍须读取或搜索真实源码。
- F22: Repo Map 的启用状态、项目根目录、仓库工作区版本、配置预算、有效预算、入选文件数量、裁剪状态、缓存命中状态、生成耗时和降级原因必须可被测试或运行状态观察。
- F23: Repo Map 不得改变普通模式、Plan Mode、权限确认、Skill、MCP、上下文压缩、会话恢复和流式回复的既有行为。

## 非功能需求
- N1: Python MVP 不依赖外部模型、Embedding、向量数据库、网络服务或远端代码索引服务。
- N2: 地图生成必须是只读操作，不修改源码、版本控制状态或用户配置，也不触发副作用权限确认。
- N3: 缓存命中且仓库关系图已就绪时，在当前 MewCode 仓库上组装 Repo Map 快照的 P95 耗时必须低于 50ms。
- N4: 文件发现、内容指纹计算、解析和关系图更新不得在 TUI 主线程执行；TUI 主线程由 Repo Map 引入的单次同步工作不得阻塞超过 16ms。
- N5: 初次索引必须可在后台执行并可取消。项目、分支或 Worktree 切换后，旧后台任务结果不得提交到新项目；组装模型请求时索引尚未完成必须按 F20 立即安全省略。
- N6: 单文件变化时只重新解析内容指纹发生变化的文件；关系图和快照可以重新计算，但不得无条件重新解析全部未变化文件。
- N7: 无论文件遍历顺序、并发完成顺序、操作系统路径表示或散列随机种子如何，地图输出都必须字节一致。并行结果必须在汇总后按稳定键排序，不能按任务完成顺序进入地图。
- N8: 文件读取、解析、排序、渲染和缓存失败不得导致 TUI 退出、会话损坏或 Agent Loop 无法继续。
- N9: 动态 Repo Map 可以增加输入 Token，也可以在 Provider 支持时形成快照级缓存，但内容相同的长期稳定 Prompt Cache 前缀必须保持字节一致。
- N10: 单元测试必须覆盖解析、关系、排序、预算、工作区版本、缓存隔离、不可信内容清理、历史隔离和 Provider 序列化；关键渲染结果必须使用精确输出 golden test。
- N11: 开发完成后必须使用 stub model 执行确定性 Agent Loop 集成测试，并使用 tmux 启动 MewCode，以真实模糊代码请求人工验证 Repo Map 注入、工具调用、回复生成和 Prompt Cache 边界。
- N12: 应准备一组目标文件不直接出现在请求中的仓库任务，分别记录启用和关闭 Repo Map 时的目标文件 Top-K 命中率与平均探索工具调用数；该质量评测用于报告效果，不作为每次 CI 的确定性门禁。

## 不做的事
- 不在首版解析 JavaScript、TypeScript、Rust、Go、Java、C/C++ 或其他非 Python 语言的符号与引用。
- 不在首版引入 Tree-sitter、多语言语法包或语言服务器协议。
- 不实现语义向量检索、Embedding、向量数据库或外部检索服务。
- 不把启发式关系称为精确调用图，也不保证识别反射、动态导入、运行时类型和动态 re-export。
- 不把 Repo Map 当作源码真值，不替代文件读取、代码搜索或测试验证。
- 不在首版为子 Agent、团队成员或隔离 Worktree 内的 Agent 分别生成专属 Repo Map。
- 不提供 Repo Map 的交互式浏览器、独立 TUI 页面或手动编辑能力。
- 不要求所有 Provider 和模型都支持 Repo Map 快照级显式缓存；不支持时必须兼容降级。
- 不为了加入 Repo Map 而改变现有 Prompt Cache 的默认保留时间、供应商 usage 判定或计费语义。
- 不把真实模型是否选择某个具体工具作为稳定 CI 的硬性通过条件。

## 验收标准
- AC1: 在默认配置下启动包含 `.py` 或 `.pyi` 文件的项目并发送用户请求，临时请求上下文自动包含 Repo Map；显式关闭后不再包含地图。（覆盖 F1、F17）
- AC2: Git 项目使用当前 Worktree 根目录，包含未跟踪但未忽略的 Python 文件；非 Git 项目应用规定的默认排除目录。符号链接和根目录外文件不会进入地图，输出路径均为 POSIX 相对路径。（覆盖 F2、F3）
- AC3: 地图能读取带合法 Python 编码声明的源码，并输出类、函数、异步函数和方法的安全签名；docstring、注释、decorator、原始默认值、字符串注解内容和控制字符不会进入地图，所有行不超过 160 个字符。（覆盖 F4、F21）
- AC4: 相对导入、绝对导入、`from` 导入、别名和同模块直接引用形成预期关系；实例方法推断、`getattr`、字符串导入、`import *`、动态 re-export、重复符号和无法消歧引用不会被伪装成精确关系。（覆盖 F5、F6）
- AC5: 当前请求明确提到文件、模块或符号时，对应候选优先于仅有图重要性的无关候选；随机化文件遍历和并发完成顺序后，最终结果仍与 golden 输出字节一致。（覆盖 F7、N7、N10）
- AC6: 完整地图块的现有 Token 估算值不超过有效地图预算，且标题、边界和提示均被计入；方法入选时保留所属类，超长签名使用完整短签名降级，超小预算下整份地图被省略而不是产生残缺条目。（覆盖 F8-F10）
- AC7: 当剩余上下文低于配置地图预算时，地图使用上下文管理器授予的较小预算；当高优先级上下文已占满空间时地图被省略，用户请求、必要工具结果、明确读取源码和必须保留的近期对话不因地图被丢弃。（覆盖 F9、F19）
- AC8: 连续多次只读工具调用保持同一仓库工作区版本和字节一致快照；成功编辑、创建或删除 Python 文件后，同一 Agent Loop 的下一次模型调用获得新版本地图，不再包含旧签名或已删除符号。（覆盖 F11、F12）
- AC9: 命令批量修改文件后，候选文件集合与内容指纹变化被识别并刷新地图；文件内容变化但修改时间不变时仍失效；新建、删除、切换分支、切换 Worktree 和切换项目均不会复用错误快照。（覆盖 F12-F14）
- AC10: 改变 Repo Map 内容、启用状态和快照缓存状态后，OpenAI 与 Anthropic 的序列化 golden test 证明从请求开头到长期稳定缓存边界的字节序列摘要完全相同，而不仅是缓存 key 相同。（覆盖 F15、N9、N10）
- AC11: 明确支持独立内容块缓存边界的 Provider 对字节一致的同一地图快照设置次级边界；地图变化只使次级快照缓存失效。旧模型或不支持显式断点的兼容接口不收到不支持的参数，仍能正常请求。（覆盖 F16）
- AC12: 无论 Provider 最终使用 system、developer 还是合成消息表示，Repo Map 都带有生成式、不可信、临时和快照级语义，不会成为用户原始输入；OpenAI 和 Anthropic 获得语义一致的地图。（覆盖 F17）
- AC13: 完成请求、触发上下文摘要、保存并恢复会话以及生成长期记忆后，聊天历史、摘要、持久化文件、恢复数据和记忆中均不存在 Repo Map 内容；下一请求只临时组装当前快照。（覆盖 F18）
- AC14: 项目无 Python 文件、功能关闭、后台索引未及时完成、语法错误、编码错误、不可读文件和缓存损坏时，MewCode 均能继续普通对话；可分析文件仍可形成地图，降级原因可观察。（覆盖 F20、F22、N8）
- AC15: 在当前 MewCode 仓库上重复组装缓存命中的地图，P95 低于 50ms；Repo Map 工作不在 TUI 主线程执行，主线程同步工作不超过 16ms；切换项目时旧后台结果被丢弃。（覆盖 N3-N5）
- AC16: 单文件修改后测试证据显示只有内容变化文件被重新解析；相同修改时间但不同内容使用不同缓存身份，解析规则或渲染规则版本变化会使对应缓存安全失效。（覆盖 F13、F14、N6）
