# Agent Evaluation Online Mode Spec

## 背景
当前 `eval/` 评测框架默认使用离线脚本化 Provider。它能稳定验证评测框架、Agent Loop、工具、权限、上下文和报告链路，但不能真实衡量模型在 MewCode 中是否会主动选择正确工具、是否能自然完成复杂任务、是否稳定处理真实上下文。

用户希望把评测改成“在线的”，也就是默认使用 MewCode 当前配置的真实 Provider 和真实模型来评估 Agent 效果，并增加更多评测用例，让报告更接近“这个 agent 靠不靠谱、好不好用”的判断。

## 目标
- 将评测默认运行模式改为在线真实模型评测，优先评估真实 Agent 行为。
- 保留明确的离线模式作为开发回归和无 API key 环境下的 smoke 检查，而不是主要评测结果。
- 增加更多覆盖面更广的评测用例，包含真实模型需要自行规划、选择工具、处理失败和验证结果的场景。
- 在线报告必须记录模型、Provider、usage、prompt cache 相关信息和人工复核事项，便于比较不同提示词或模型配置。
- 在线评测失败时应能区分“评测框架错误”“模型行为未达标”“环境或配置不可用”。

## 功能需求
- F1: 默认评测命令必须使用真实 MewCode 配置加载 Provider，并通过真实模型驱动 Agent，而不是默认使用脚本化 Provider。
- F2: CLI 必须显式支持 `online` 和 `offline` 两种模式；`online` 为默认模式，`offline` 仅用于 smoke 或本地回归。
- F3: 在线模式缺少配置、API key、网络或 Provider 初始化失败时，必须返回清晰错误，不能伪装成 Agent 能力失败。
- F4: 在线模式必须继续复用真实 `AgentLoopRunner`、工具、权限、上下文和 Provider 抽象，不绕过核心 Agent 路径。
- F5: 在线模式报告必须记录 Provider、模型、usage、prompt cache 命中或不支持状态、运行耗时、失败原因和人工复核项。
- F6: 初始在线用例必须比现有 7 个离线用例更多，至少覆盖 30 个用例，并包含代码阅读、文件修改、测试修复、权限拒绝、上下文压缩、Skill、子 Agent、命令失败恢复、计划模式、会话连续性、提示词缓存观察和多文件任务。
- F7: 在线用例必须尽量避免真实破坏性操作；写入和命令类用例必须在临时或隔离 workspace 中执行。
- F8: 自动评分仍只判断可观察证据；主观质量、交互体验和代码审查质量必须标记为 `needs_review`，不能声称完全自动判断。
- F9: 在线模式必须支持只运行指定用例，便于调试单个真实模型失败。
- F10: 测试套件必须覆盖在线模式的加载、配置错误、报告字段和 CLI 参数行为，但不得要求真实 API key 或真实网络才能通过。
- F11: 离线脚本化 Provider 可以保留给单测和 smoke，但报告和 README 必须明确它不是主要质量评测。

## 非功能需求
- N1: 在线评测可能较慢、产生费用且结果不稳定，文档和报告必须明确说明。
- N2: 在线评测不得把 API key、完整本地敏感路径或过长工具输出写入报告。
- N3: 增加用例时应保持 JSON 可编辑，不要求用户改核心代码。
- N4: 自动化测试必须在无网络和无真实 API key 环境下稳定通过。
- N5: 在线评测命令的退出码必须能用于 CI 或人工脚本判断。

## 不做的事
- 不在本阶段接入外部排行榜或公开基准平台。
- 不保证真实模型每次运行结果完全一致。
- 不把人工复核维度自动判定为绝对通过。
- 不要求 pytest 调真实模型或真实网络。
- 不执行真实删除、推送、部署、系统级修改等高风险操作。
- 不在本阶段自动比较两次评测报告的趋势；只保证报告包含可比较字段。

## 验收标准
- AC1: 默认运行 `python eval/run_eval.py ...` 时进入在线真实模型模式；用户显式传入离线模式时才使用脚本化 Provider。（覆盖 F1、F2、F11）
- AC2: 在线模式缺少配置或 Provider 不可用时给出明确错误和非零退出码，且不会生成误导性的 Agent 能力失败报告。（覆盖 F3、N5）
- AC3: 在线模式通过真实 Agent 核心路径运行，并在报告中包含 Provider、模型、usage、prompt cache、工具轨迹、停止原因和人工复核项。（覆盖 F4、F5、F8）
- AC4: 评测用例总数至少 30 个，覆盖代码阅读、文件修改、测试修复、权限拒绝、上下文压缩、Skill、子 Agent、命令失败恢复、计划模式、会话连续性、提示词缓存观察和多文件任务。（覆盖 F6、F7）
- AC5: 单元测试和 CLI 测试不依赖真实 API key 或网络，但能验证在线模式的配置分支、Provider 注入分支和报告字段。（覆盖 F10、N4）
- AC6: 写入和命令类在线用例在临时或隔离 workspace 中运行，不污染项目根目录。（覆盖 F7、N2）
- AC7: README 明确说明在线模式的费用、耗时、不稳定性、人工复核边界，以及离线模式只用于 smoke/回归。（覆盖 N1、F8、F11）
