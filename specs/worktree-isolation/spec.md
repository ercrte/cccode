# MewCode Worktree 隔离 Spec

## 背景
MewCode 已经支持定义式与 Fork 式子 Agent，并隔离子 Agent 的消息、权限状态、上下文管理、文件读取缓存和 Token 记录。当前主 Agent 与所有子 Agent 仍共享同一个项目工作目录和文件系统视图。当主 Agent 与子 Agent 并行修改文件时，一方的未提交改动会立即被另一方看到，可能导致覆盖、误读或相互干扰。

本阶段为需要写代码的定义式子 Agent 提供可声明的 Worktree 隔离模式。启用后，每个子 Agent 在同一 Git 仓库内获得独立目录和独立分支，仍共享仓库对象，但所有工具调用、项目指令、上下文和记忆均以该隔离目录为边界。该能力是子 Agent 的内部运行机制，不向用户或模型新增 Worktree 管理命令。

## 目标
- 允许定义式子 Agent 通过角色声明请求独立 Worktree，并在委派时自动完成创建、使用和退出。
- 保证主 Agent 与多个隔离子 Agent 可以并行读写文件，彼此不覆盖未提交改动。
- 提供安全、可恢复的 Worktree 完整生命周期，并在删除前保护未提交修改和未推送提交。
- 在隔离目录创建后按项目配置恢复必要的本地运行环境，同时避免复制无关缓存或越界访问。
- 让所有目录相关运行状态天然按绝对工作目录隔离，不依赖切换目录时清理全局缓存。
- 自动清理已过期且确认安全的临时 Worktree，避免长期积累无用目录和分支。

## 功能需求
- F1: 定义式子 Agent 的角色声明必须支持 `isolation: worktree`；未声明该字段时保持现有共享主工作目录的行为，声明其他值时该角色必须被判定为无效。Fork 式子 Agent 不支持 Worktree 隔离，也不扩展委派参数。
- F2: Worktree 生命周期只作为子 Agent 内部能力使用；系统不得为用户或模型新增创建、进入、退出、删除或切换 Worktree 的命令与工具。
- F3: 每次隔离委派必须基于主工作目录当前已提交的 `HEAD` 创建独立分支和独立工作目录。主工作目录存在未提交修改时仍允许创建，这些未提交修改不得进入隔离目录。
- F4: 隔离目录必须位于仓库内部的专用忽略区域，不得被主工作目录作为普通项目内容追踪。目录名称必须由已校验的角色名和内部任务 ID 生成，任务描述或其他模型文本不得参与路径生成。
- F5: 所有 Worktree 相对名称必须经过统一安全校验：完整名称长度为 1–200 个字符；允许使用 `/` 分隔嵌套段；每段长度为 1–64 个字符，必须以 ASCII 字母或数字开头，其余字符只能是 ASCII 字母、数字、下划线或连字符；必须拒绝空段、`.`、`..`、绝对路径、反斜杠和任何越过专用根目录的结果。
- F6: 创建操作必须拒绝目标目录、分支或任务归属冲突，不得覆盖已有文件、复用其他任务的目录或静默重置已有分支。
- F7: 创建成功后必须在隔离目录中写入可供恢复校验的元数据，至少能确认仓库身份、任务 ID、角色、分支、创建基线和创建时间。
- F8: 当目标目录已经存在时，系统必须进入快速恢复流程：只读取文件系统中的恢复元数据，不调用 Git；元数据与当前仓库及任务完全匹配时恢复使用，缺失、损坏或不匹配时拒绝恢复且不修改该目录。
- F9: 进入隔离模式后，子 Agent 的每次工具调用都必须显式使用隔离目录作为工作目录，不得通过修改进程全局当前目录实现切换；主 Agent 和其他子 Agent 的工作目录不得因此改变。
- F10: 与文件内容、系统提示词、项目指令、上下文存储和项目记忆有关的目录相关缓存或状态必须以规范化绝对路径作为身份键或边界，使同一相对路径在不同 Worktree 中互不复用；进入和退出 Worktree 时不要求清空其他目录的缓存。
- F11: 隔离子 Agent 的运行时提示必须明确说明当前隔离目录、主工作目录、当前分支，以及所有文件操作必须限定在隔离目录内；主 Agent 收到的任务结果必须包含保留目录和分支信息，或已清理结论。
- F12: 项目配置必须支持显式声明环境初始化规则，包括复制项、软链目录和需要补齐的被忽略文件。所有规则只接受相对仓库根目录的路径，源与目标使用相同相对路径；必须拒绝绝对路径、路径遍历、空路径和越过主工作目录或隔离目录边界的结果。
- F13: 环境初始化必须按以下语义执行：复制项在隔离目录中创建独立副本；软链目录指向主工作目录内同路径目标；需补齐的忽略文件从主工作目录复制到隔离目录。规则引用的源不存在、目标冲突、目标类型不符或操作失败时，隔离委派必须以可理解错误停止，不得带着半有效环境运行。
- F14: 隔离目录必须继承主工作目录当前生效的 Git hooks 配置；主目录没有自定义 hooks 路径时，隔离目录继续使用仓库共享 hooks。隔离配置不得修改主工作目录原有 hooks 行为。
- F15: 子 Agent 结束、失败或取消时必须退出隔离运行状态并检查变更。仅当工作树干净且相对创建基线没有新增提交时，系统才自动删除本次 Worktree 及其临时分支；存在未提交修改、未跟踪文件或新增提交时必须保留，并向主 Agent 说明原因、目录和分支。
- F16: 删除操作默认必须拒绝删除存在未提交修改、未跟踪文件或未推送新增提交的 Worktree。没有远端跟踪关系时，相对创建基线的全部新增提交都视为未推送；有远端引用时，只有确认新增提交均已存在于远端引用中，才视为已推送。
- F17: 系统必须在启动时执行一次过期清理，并在运行期间默认每小时执行一次；默认过期时间为 7 天，清理间隔和过期时间可通过项目配置调整且必须为正值。清理任务不得阻塞正常对话、子 Agent 委派或应用退出。
- F18: 后台清理只能处理专用忽略区域内、具有有效归属元数据、已超过过期时间且不属于运行中任务的候选目录；删除前仍必须执行变更与未推送提交保护。工作树干净且新增提交均已推送的过期 Worktree 可以被清理。
- F19: 后台清理必须采用三层独立安全过滤：路径必须规范化后位于专用根目录内；恢复元数据必须能证明该目录由当前仓库的 MewCode 创建；当前任务状态和 Git 保护检查必须共同确认可删除。任一层无法确认时必须跳过并记录原因。
- F20: Worktree 创建、环境初始化、恢复、进入、退出或清理失败时，错误必须包含当前阶段和可操作原因；失败不得改变主 Agent 的工作目录，不得删除无法确认安全的目录，也不得导致 MewCode 主会话不可继续。

## 非功能需求
- N1: 所有路径输入在执行文件系统或 Git 操作前完成校验与边界确认，不能依赖字符串前缀判断目录归属。
- N2: Worktree 生命周期操作必须对同一目标串行化，避免两个并行委派创建、恢复或删除同一目录和分支。
- N3: Worktree 与分支创建必须共享同一仓库对象，不复制完整仓库历史；大型依赖只通过显式软链规则复用。
- N4: 环境初始化不得隐式扫描或复制全部 Git 忽略内容，不得自动执行项目提供的 shell 初始化命令，不得读取仓库外源路径。
- N5: 快速恢复路径不得调用 Git，也不得写入、修复或删除现有目录；其结果必须可以通过替换 Git 执行器的测试明确验证。
- N6: 自动清理采用保守失败策略；元数据损坏、Git 状态未知、远端可达性无法确认、目录正在使用或任一安全检查异常时均保留候选项。
- N7: 路径、分支、生命周期阶段、保留或清理原因必须可通过日志或子 Agent 结果观察，但不得暴露本地配置文件内容或其他敏感数据。
- N8: 主要生命周期、安全校验、恢复、保护删除和过期清理行为必须能在临时 Git 仓库中自动化测试，不依赖真实模型或远端服务。

## 不做的事
- 不实现 Worktree 分支与主分支之间的自动合并、变基、冲突解决或提交挑选；上层仍使用 Git 完成合并。
- 不实现主工作目录与隔离目录之间的实时文件同步，也不把主目录未提交修改复制到 Worktree。
- 不实现多个子 Agent 的团队编排、任务依赖图、并行调度策略或结果自动汇总。
- 不为 Fork 式子 Agent 提供 Worktree 隔离，也不允许通过委派参数临时覆盖角色的隔离声明。
- 不向用户或模型提供 Worktree 生命周期命令、工具或交互式删除确认界面。
- 不自动提交、推送或丢弃子 Agent 的改动，不因超过保留期限而绕过变更保护。
- 不自动发现 `.env`、虚拟环境、依赖目录或其他忽略文件；只有项目显式配置的初始化项会被处理。
- 不允许环境初始化规则使用仓库外源路径、自定义目标路径或任意 shell 命令。

## 验收标准
- AC1: 未声明 `isolation` 的定义式角色和所有 Fork 式子 Agent 继续使用主工作目录，现有委派行为不变；角色声明未知 `isolation` 值时被报告为无效且不能启动。（覆盖 F1、F2）
- AC2: 声明 `isolation: worktree` 的定义式角色被委派后，子 Agent 获得独立目录和独立分支；主 Agent 的当前目录、分支和未提交文件保持不变。（覆盖 F1、F3、F9）
- AC3: 主工作目录存在未提交修改时仍能创建隔离目录；隔离目录只包含当前 `HEAD` 的受追踪内容，不包含主目录未提交修改。（覆盖 F3）
- AC4: 两个隔离子 Agent 并行修改相同相对路径时，各自只能看到自己的修改，主工作目录文件不发生变化。（覆盖 F4、F9、F10）
- AC5: 生成的目录位于仓库内部专用忽略区域，并且主工作目录状态不会把其中内容报告为待追踪项目文件。（覆盖 F4）
- AC6: 合法的单段和嵌套名称通过校验；超过总长度或段长度、非法字符、空段、`.`、`..`、绝对路径、反斜杠及归一化后越界的名称全部在任何文件系统或 Git 写操作前被拒绝。（覆盖 F5）
- AC7: 已存在的无关目录、被其他任务占用的目录或冲突分支不会被覆盖、重置或复用，委派收到明确冲突错误。（覆盖 F6）
- AC8: 首次创建成功后能读取到完整恢复元数据；仓库、任务、角色、分支、基线和创建时间均与本次委派一致。（覆盖 F7）
- AC9: 目标目录已存在且恢复元数据完全匹配时，委派恢复同一隔离目录并且没有执行任何 Git 命令；元数据缺失、损坏或不匹配时只读失败，目录内容保持不变。（覆盖 F8）
- AC10: 隔离子 Agent 的文件工具、命令工具和 Hook 命令均在隔离目录执行；运行期间进程全局当前目录与主 Agent 工具工作目录保持不变。（覆盖 F9、F14）
- AC11: 两个 Worktree 中相同相对路径的文件内容、项目指令、系统提示、上下文存储和项目记忆不会发生跨目录缓存命中或状态串用；切换任务不需要全局清缓存。（覆盖 F10）
- AC12: 隔离子 Agent 收到的运行时提示包含隔离目录、主工作目录、当前分支和路径限制；任务结束结果明确报告 Worktree 已清理或给出保留目录、分支及原因。（覆盖 F11）
- AC13: 合法复制规则会产生独立副本，修改副本不改变主目录源文件；合法软链规则指向主目录内同路径目标；合法忽略文件规则会补齐对应文件。（覆盖 F12、F13）
- AC14: 初始化规则中的绝对路径、空路径、路径遍历、仓库外源、目标越界或自定义目标均在执行前被拒绝；系统不会自动复制未声明的忽略内容。（覆盖 F12、N4）
- AC15: 初始化源缺失、目标冲突、目标类型错误或复制、软链失败时，子 Agent 不会开始执行任务，主会话收到包含初始化阶段和原因的错误。（覆盖 F13、F20）
- AC16: 主工作目录配置自定义 Git hooks 时，隔离目录提交会触发同一套 hooks；未自定义时使用共享 hooks；初始化前后主工作目录的 hooks 行为一致。（覆盖 F14）
- AC17: 子 Agent 结束时，工作树干净且没有新增提交的 Worktree 及临时分支会自动删除，并向主 Agent 报告已清理。（覆盖 F15）
- AC18: 子 Agent 结束、失败或取消时，只要存在未提交修改、未跟踪文件或新增提交，Worktree 和分支都会保留，结果包含目录、分支和具体保护原因。（覆盖 F15）
- AC19: 直接请求删除有未提交修改或未跟踪文件的 Worktree 会被拒绝；无远端跟踪关系且有新增提交时也会被拒绝。（覆盖 F16）
- AC20: 有远端引用时，至少一个新增提交未包含在远端引用中会阻止删除；全部新增提交均可从远端引用到达且工作树干净时允许删除。（覆盖 F16）
- AC21: MewCode 启动时会执行一次非阻塞过期清理，持续运行时按默认每小时再次执行；配置新的正数清理间隔和 7 天以外的正数过期时间后按配置生效，零、负数或非数值配置在加载时被拒绝。（覆盖 F17）
- AC22: 未过期、属于运行中任务、位于专用根目录外、元数据无效或无法证明属于当前仓库的目录不会被后台清理。（覆盖 F18、F19）
- AC23: 已过期、工作树干净、全部新增提交已推送且通过三层安全过滤的 Worktree 可以被后台删除；存在未提交内容或未推送提交的过期 Worktree 仍被保留。（覆盖 F18、F19）
- AC24: 清理过程中遇到损坏元数据、Git 状态检查失败、远端可达性未知或删除异常时，候选目录保留，错误被记录，正常对话和其他子 Agent 继续运行。（覆盖 F19、F20）
- AC25: 两个并行请求针对同一目标执行创建、恢复或删除时，操作不会交错破坏目录、分支或元数据，至多一个请求成功进入该目标。（覆盖 F6、N2）
- AC26: 任一生命周期阶段失败后，主 Agent 工作目录未改变、主会话仍可继续发起普通工具调用或新的委派，且系统没有删除无法确认安全的目录。（覆盖 F20）
