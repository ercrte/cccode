# JulyCode Hook System Spec

## 背景
JulyCode 已经具备 Agent Loop、本地工具系统、权限系统、上下文管理、会话恢复和长期记忆。当前这些能力大多由固定流程驱动，用户或模型仍需要手动关注一些重复工作，例如在特定时机格式化文件、在工具执行前做项目级安全检查、在轮次开始时补充临时上下文，或在系统状态变化后通知外部服务。

本阶段要引入声明式 Hook 系统，让用户用“事件 + 条件 + 动作”描述自动化规则。Hook 必须在 Agent 生命周期的关键节点被触发，条件清晰、动作固定、失败不影响主流程。工具执行前的 Hook 还必须能作为细粒度拦截点，把拒绝原因作为工具结果反馈给模型，使模型可以调整后续行动。

## 目标
- JulyCode 可以从主配置中加载 Hook 规则，并在启动或配置加载阶段集中校验。
- JulyCode 可以在会话级、轮次级、消息级、工具级和少量系统级事件发生时触发匹配的 Hook。
- JulyCode 可以用统一的“事件 + 条件 + 动作”结构描述 Hook 规则，条件可省略，事件和动作必须声明。
- JulyCode 可以在工具执行前根据工具名称和参数执行细粒度拦截；被拦截的工具不会真正执行，拒绝原因会作为工具结果回灌给模型。
- JulyCode 可以复用权限规则的匹配语义来表达 Hook 条件，并支持精确、反向、正则和 glob 匹配。
- JulyCode 可以执行四类 Hook 动作：执行 shell 命令、注入提示词、发送 HTTP 请求、声明子 Agent 动作占位。
- JulyCode 可以控制 Hook 是否当前运行期只执行一次、是否后台异步执行，以及 shell 命令动作的超时时间。
- JulyCode 在 Hook 动作运行失败时只记录日志或状态事件，不中断 Agent 主流程。

## 功能需求
- F1: Hook 规则必须由事件、条件和动作三部分组成；条件可以省略表示无条件触发，事件和动作必须存在。
- F2: Hook 规则必须从主配置的 `hooks` 声明中加载；未声明时视为空规则集合，不影响 JulyCode 启动和 Agent 行为。
- F3: Hook 规则必须在生效前集中校验；事件缺失、动作缺失、未知事件、未知动作、条件格式无效、执行控制冲突或动作必填字段缺失都必须被报告为配置错误。
- F4: Hook 事件必须覆盖会话级事件，包括会话开始和会话结束。
- F5: Hook 事件必须覆盖轮次级事件，包括用户任务轮次开始和用户任务轮次结束。
- F6: Hook 事件必须覆盖消息级事件，包括用户消息进入 Agent 流程和模型消息完成。
- F7: Hook 事件必须覆盖工具级事件，包括工具执行前和工具执行后；工具执行前事件必须发生在权限、策略和工具真实执行之前可观测的位置。
- F8: Hook 事件必须覆盖少量系统级事件，至少包括上下文压缩完成、Agent 因明确停止条件停止、Agent 运行错误。
- F9: Hook 条件可以基于事件携带的稳定字段进行匹配；不同事件必须暴露与自身语义相关的字段，例如模式、消息内容、工具名称、工具参数、工具结果、停止原因或错误类别。
- F10: Hook 条件必须支持精确匹配、反向匹配、正则匹配和 glob 匹配，并与权限规则使用一致的匹配语义。
- F11: Hook 条件的逻辑组合必须只能选择“全部满足”或“任一满足”其中一种；同一条规则内不得混用两种组合方式。
- F12: 当条件引用的字段在当前事件中不存在时，该条件必须按未匹配处理；未匹配不得导致 Hook 系统报错。
- F13: 工具执行前 Hook 必须能够基于工具名称和完整工具参数决定是否拦截当前工具调用。
- F14: 当工具执行前 Hook 产出拒绝结果时，JulyCode 必须跳过该工具的真实执行，并把拒绝原因作为该工具调用的失败结果回灌给模型。
- F15: 工具执行前 Hook 的拒绝结果不得直接终止 Agent Loop；只要未触发既有停止条件，模型必须有机会根据工具失败结果调整下一步。
- F16: 未产出拒绝结果的工具执行前 Hook 不得改变工具原有权限、策略和执行流程。
- F17: shell 命令动作必须能在当前项目工作目录下执行命令，并能记录退出码、标准输出、标准错误、超时和失败信息。
- F18: 提示词注入动作必须能把声明的提示内容加入后续模型请求的运行时上下文；注入内容不得伪装成用户消息，也不得永久写入会话历史。
- F19: HTTP 请求动作必须能向声明的地址发送请求，并能记录响应状态、响应摘要、超时和失败信息。
- F20: 子 Agent 动作必须能被声明和校验，但本阶段触发时只产生占位状态，不启动真实子 Agent，也不向模型伪造子 Agent 结果。
- F21: Hook 执行控制必须支持当前运行期只执行一次；同一条规则命中多次时，只执行第一次，重启后不要求保留已执行标记。
- F22: Hook 执行控制必须支持后台异步执行；后台动作不得阻塞 Agent 主流程，执行结果只能通过日志或状态事件观察。
- F23: Hook 执行控制必须支持 shell 命令动作超时；超时后该动作被视为失败并记录，不得无限等待。
- F24: 工具执行前这类可拦截事件不得配置后台异步执行；相关配置必须在集中校验阶段报错。
- F25: Hook 动作运行失败、超时、HTTP 错误或子 Agent 占位不可运行时，只能记录日志或状态事件，不得导致 Agent Loop、TUI 或会话状态中断。
- F26: 多条 Hook 规则命中同一事件时，必须按配置中的声明顺序执行；本阶段不支持显式优先级。
- F27: Hook 执行结果默认不得自动注入模型上下文；只有提示词注入动作和工具拦截结果会影响模型可见上下文。

## 非功能需求
- N1: Hook 系统必须集中接入 Agent 生命周期，避免不同模块各自散落实现触发逻辑。
- N2: Hook 配置格式必须便于人工阅读和手写；错误信息必须能指出哪条规则或哪个字段无效。
- N3: Hook 条件匹配和动作执行必须可测试，且不依赖真实外部模型才能验证主要行为。
- N4: Hook 动作输出和错误信息必须延续现有脱敏要求，不得泄露配置密钥、请求头密钥或环境变量敏感值。
- N5: Hook 系统不得降低现有权限系统、Plan Mode、Skill 工具白名单、上下文管理和 Agent 停止条件的约束能力。
- N6: 后台异步 Hook 不得让 TUI 输入区永久不可用，也不得阻止 JulyCode 正常退出。
- N7: Hook 失败日志或状态事件必须足够定位问题，但不能要求用户阅读内部堆栈才能理解常见配置或运行错误。

## 不做的事
- 不实现子 Agent 动作的真实运行、调度、结果汇总或模型上下文回写。
- 不实现“只跑一次”标记的跨启动持久化；重启 JulyCode 后可以重新执行。
- 不实现 Hook 执行顺序的显式优先级、排序权重或跨来源优先级策略。
- 不实现独立 Hook 配置文件；本阶段只使用主配置中的 `hooks` 声明。
- 不实现交互式 Hook、需要用户二次确认的 Hook 或 Hook 运行中的输入接管。
- 不实现长期审计日志、Hook 执行报表或远端规则同步。
- 不允许 Hook 绕过高危命令硬拒绝、项目路径沙箱、Plan Mode 只读限制或 Skill 工具白名单。
- 不把 shell 命令和 HTTP 动作的输出默认注入模型上下文。

## 验收标准
- AC1: 当主配置没有声明 `hooks` 时，JulyCode 正常启动，普通对话和工具调用行为与无 Hook 系统一致。
- AC2: 当 Hook 规则缺少事件或动作时，JulyCode 在配置加载阶段给出清晰配置错误，不以半有效规则继续运行。
- AC3: 当 Hook 规则使用未知事件、未知动作、无效条件组合、无效匹配表达式或可拦截事件的后台异步配置时，JulyCode 给出清晰配置错误。
- AC4: 会话开始、会话结束、轮次开始、轮次结束、用户消息进入流程、模型消息完成、工具执行前、工具执行后、上下文压缩完成、Agent 停止和 Agent 错误事件都可以触发匹配的 Hook。
- AC5: 省略条件的 Hook 在对应事件发生时无条件触发。
- AC6: 使用“全部满足”的 Hook 只有在所有条件都匹配时触发；任一条件不匹配时不触发。
- AC7: 使用“任一满足”的 Hook 只要至少一个条件匹配就触发；全部不匹配时不触发。
- AC8: 同一条 Hook 规则同时声明“全部满足”和“任一满足”时，配置校验失败。
- AC9: Hook 条件可以用精确、反向、正则和 glob 匹配事件字段，匹配结果符合权限规则的同类语义。
- AC10: Hook 条件引用当前事件不存在的字段时，该条件按未匹配处理，Agent 主流程继续。
- AC11: 工具执行前 Hook 可以匹配具体工具名称和参数；匹配后产出拒绝结果时，目标工具不执行。
- AC12: 被工具执行前 Hook 拦截后，模型收到该工具调用的失败结果，结果中包含拒绝原因，Agent Loop 可继续请求模型调整。
- AC13: 工具执行前 Hook 没有产出拒绝结果时，工具继续经过原有权限、策略和执行流程。
- AC14: shell 命令动作触发后会在当前项目工作目录执行；成功、失败和超时都能通过日志或状态事件观察。
- AC15: shell 命令动作超过声明超时时间后被终止并记录失败，Agent 主流程不中断。
- AC16: 提示词注入动作触发后，后续模型请求能看到注入内容；会话历史中不会出现伪造的用户消息。
- AC17: HTTP 请求动作触发后会发送声明的请求；响应成功、响应失败和请求超时都能通过日志或状态事件观察。
- AC18: 子 Agent 动作触发时只记录占位状态，不启动真实子 Agent，不阻塞 Agent 主流程。
- AC19: 配置为只跑一次的 Hook 在当前运行期第一次命中时执行，后续再次命中不执行；重启后可以重新执行。
- AC20: 配置为后台异步的非拦截 Hook 不阻塞 Agent 主流程；后台动作失败只记录日志或状态事件。
- AC21: Hook 动作运行时抛出异常、命令失败、HTTP 失败或占位动作不可运行时，TUI 不崩溃，输入区恢复可用，会话状态保持可继续。
- AC22: 多条 Hook 规则匹配同一事件时，按配置声明顺序执行；没有显式优先级字段也能得到稳定顺序。
- AC23: Hook 不会绕过现有权限系统、Plan Mode、Skill 工具白名单或项目路径沙箱；这些限制仍按原有行为生效。
