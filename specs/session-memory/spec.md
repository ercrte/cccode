# JulyCode 会话恢复与长期记忆 Spec

## 背景
JulyCode 当前已经具备全屏对话、结构化系统提示、工具调用、Agent Loop、Plan Mode、权限控制、MCP 工具接入和运行期上下文压缩能力。现有会话主要保存在当前进程内，上下文摘要也只服务于当前运行期；README 也明确记录了当前不支持跨启动历史恢复、项目指令文件加载和自动记忆。

本阶段要让 JulyCode 在同一项目中越用越理解项目和用户：启动时自动加载项目指令、用户偏好、项目知识和最近会话；会话中断后再次启动可以默认接上最近进度；每轮自然完成后可以沉淀长期笔记。系统需要把项目指令、会话存档和自动笔记分层管理，既减少“每次失忆”，也避免把临时对话、长期偏好和项目规则混在一起。

## 目标
- 新会话启动时默认自动恢复同一项目最近未过期会话，让用户可以平滑接着做上次的工作。
- JulyCode 在处理用户请求前已经加载项目指令和记忆索引，使模型能直接遵循项目规则、用户偏好和已有项目知识。
- 项目指令支持项目管理目录级、项目根级和用户级三层加载，项目级优先于用户级，高优先级内容在上下文中排在更前面。
- 会话存档以追加方式持久保存，恢复时可以容忍局部损坏，并且不依赖额外元数据文件保持同步。
- 会话恢复能处理坏记录、未配对工具调用、上下文超限、长时间间隔和过期清理等异常。
- 自动笔记按用户偏好、纠正反馈、项目知识和参考资料四类沉淀，并区分用户级与项目级存储。
- 记忆索引保持短小、可注入、可被模型直接阅读，不引入向量检索或复杂召回流程。

## 功能需求
- F1: JulyCode 启动时必须按项目管理目录级、项目根级、用户级三层加载指令文件；项目管理目录级优先于项目根级，项目根级优先于用户级，高优先级内容必须在最终上下文中排在低优先级内容之前。
- F2: 项目指令必须支持在指令文件中引用其他文本文件；引用展开必须限制嵌套深度、防止循环引用，并拒绝跳出允许目录的引用路径。项目级引用不得跳出项目目录，用户级引用不得跳出用户级 JulyCode 目录。
- F3: 指令文件缺失时系统必须安静跳过；指令文件或引用文件无法读取、引用非法或嵌套过深时，系统必须继续启动，并向用户或日志提供可理解的告警。
- F4: JulyCode 启动时必须默认选择同一项目中最近的未过期会话进行恢复；用户也必须有明确方式启动空会话，避免被旧会话污染。
- F5: 每个会话必须以唯一会话标识存档；同一秒内创建多个会话时不得发生文件名冲突。
- F6: 会话消息必须以追加写入方式逐条保存；崩溃或异常退出后，最多只允许丢失或损坏最后一条未完整写入的记录。
- F7: 会话列表所需的会话标识、标题、消息数、最近更新时间和过期判断必须能从会话存档本身计算出来，不得依赖单独维护的元数据文件。
- F8: 恢复会话时，无法解析的坏记录必须被跳过并记录告警，其他有效记录仍应恢复。
- F9: 恢复会话时，如果发现助手工具调用没有对应工具结果，或工具结果没有可匹配的工具调用，系统必须在协议安全边界截断历史，避免把无效工具历史发送给模型。
- F10: 恢复后的会话如果超过当前上下文预算，系统必须先尝试执行一次压缩；压缩后仍明显超限时，必须停止恢复该会话并给出清晰说明，而不是发送超预算请求。
- F11: 恢复的会话如果距离上次活动时间过久，系统必须向模型上下文插入一条时间跨度提醒，让模型知道当前任务可能已跨越较长时间。
- F12: 超过 30 天未活动的会话必须被定期清理；清理不得影响未过期会话、项目指令和长期笔记。
- F13: 当一轮 Agent Loop 因模型给出最终回复且不再请求工具而自然结束后，系统必须异步发起自动笔记更新；取消、报错、达到迭代上限或等待工具结果时不得错误触发同一轮自然完成笔记。
- F14: 自动笔记必须按用户偏好、纠正反馈、项目知识和参考资料四类组织；去重、合并和是否更新既有笔记由更新过程判断。
- F15: 自动笔记必须区分用户级与项目级：跨项目通用的偏好和纠正反馈进入用户级记忆，项目相关事实、约定和参考资料进入项目级记忆。
- F16: 每条自动笔记必须能以带结构化元信息的 Markdown 形式独立存储、独立更新，并包含足够元信息支持后续生成索引、审查来源和判断类别。
- F17: 用户级和项目级记忆索引必须在处理用户请求前注入模型上下文，使模型表现得像已经读过这些记忆。
- F18: 记忆索引必须有体量上限，单个索引文件不得超过 200 行或 25KB；超过上限时必须通过合并、摘要或裁剪保持可注入。
- F19: 自动记忆失败、索引更新失败或会话保存失败不得导致 TUI 退出或阻断用户继续对话；系统必须保留可理解的错误提示或日志。
- F20: 项目指令、恢复会话、记忆索引和运行期上下文摘要同时存在时，系统必须保持清晰优先级和边界，避免把长期记忆伪装成用户刚刚说过的话。
- F21: 本阶段新增能力不得破坏现有普通聊天、工具调用、Plan Mode、`/do`、权限确认、MCP 工具接入、上下文压缩和流式显示行为。

## 非功能需求
- N1: 启动恢复和记忆注入应保持可解释，用户能判断当前是否恢复了旧会话、加载了哪些层级的知识，以及出现了哪些可忽略或需处理的问题。
- N2: 会话追加写入、恢复扫描和索引注入应适合日常编程会话规模，不应让普通启动和短对话出现明显卡顿。
- N3: 指令引用和会话恢复必须遵守项目路径边界和现有安全约束，不得通过引用或恢复读取项目外敏感文件。
- N4: 自动记忆应在 Agent Loop 自然停下后后台执行，不应明显延迟最终回复展示。
- N5: 长期记忆内容必须保守沉淀，不应把临时任务细节、敏感密钥、短期工具输出或未经用户确认的猜测提升为长期事实。
- N6: 用户可见提示必须使用中文，说明应足够具体，能帮助用户判断是继续当前恢复会话、启动空会话还是手动处理异常。
- N7: 新增持久化文件应位于 JulyCode 管理目录下，避免污染项目业务源码目录。

## 不做的事
- 不实现向量数据库、嵌入召回或 RAG 检索。
- 不实现团队共享记忆、跨用户同步或远端记忆服务。
- 不实现跨项目自动合并项目记忆。
- 不为会话列表单独维护需要与会话存档同步的元数据文件。
- 不要求恢复所有过期会话，也不保证坏记录之后的所有历史都能被完整恢复。
- 不把自动笔记作为不可更改的事实来源；模型仍应在需要时读取项目文件或向用户确认。
- 不改变现有工具权限模型、路径沙箱规则或 MCP 工具业务能力。

## 验收标准
- AC1: 当项目管理目录级、项目根级和用户级指令同时存在时，模型请求上下文中内容按项目管理目录级、项目根级、用户级排列，且缺失文件不会阻止启动。
- AC2: 当指令文件引用其他文件时，合法引用会被展开；循环引用、嵌套过深和跳出允许目录的引用会被拦截并产生可理解告警。
- AC3: 在同一项目中退出后重新启动 JulyCode，系统默认恢复最近未过期会话，用户可选择启动空会话。
- AC4: 同一秒内创建多个会话时，每个会话都有不同标识和不同存档文件。
- AC5: 会话追加写入过程中模拟最后一条记录损坏后，恢复时坏记录被跳过，其余有效消息仍可用于继续对话。
- AC6: 会话列表的标题、消息数和最近更新时间可通过扫描会话存档得到；删除任何额外元数据文件不影响列表计算。
- AC7: 恢复包含未配对工具调用或工具结果的会话时，系统在安全边界截断历史，后续模型请求不包含无效工具历史。
- AC8: 恢复超出上下文预算的会话时，系统先尝试一次压缩；压缩成功后可以继续请求模型，压缩后仍超限时给出清晰停止说明。
- AC9: 恢复距离上次活动时间过久的会话后，下一次模型上下文包含时间跨度提醒。
- AC10: 超过 30 天未活动的会话会被清理，未过期会话、项目指令和长期笔记保持不变。
- AC11: 一轮 Agent Loop 自然完成后，系统会异步更新自动笔记；工具调用中、取消、报错和迭代上限停止不会被当作自然完成。
- AC12: 自动笔记能分别产生或更新用户偏好、纠正反馈、项目知识和参考资料四类内容，并能区分用户级与项目级存储位置。
- AC13: 自动笔记重复表达同一事实时，更新结果不会在索引中产生明显重复条目。
- AC14: 记忆索引在下一轮用户请求前已注入上下文，模型可以基于索引中的偏好或项目知识调整回复。
- AC15: 记忆索引超过 200 行或 25KB 前会被控制体量，最终可注入索引满足上限要求。
- AC16: 自动记忆或索引更新失败时，用户仍可继续对话，TUI 不退出，错误信息可被观察到。
- AC17: 项目指令、会话恢复、记忆索引和运行期上下文摘要同时存在时，模型上下文能区分它们的来源与优先级。
- AC18: 新增能力启用后，现有普通聊天、工具调用、Plan Mode、`/do`、权限确认、MCP 工具、上下文压缩和流式显示测试仍通过。
- AC19: 端到端场景中，用户先让 JulyCode 记住一个项目约定并完成一次工具任务，退出后重新启动；JulyCode 自动恢复最近会话并在下一次请求前注入该项目约定，随后能按该约定继续调用工具和回复。
