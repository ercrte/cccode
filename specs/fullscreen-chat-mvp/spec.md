# JulyCode 全屏对话 MVP Spec

## 背景
JulyCode 是一个终端 AI 编程助手。当前项目从零开始，第一步只实现终端内的纯对话体验：用户启动后进入全屏交互界面，输入问题，系统调用配置好的大模型后端，并将回复以流式方式展示。该阶段不包含工具调用、文件操作、代码编辑等 agent 能力。

## 目标
- 用户可以在终端中启动 JulyCode，并进入全屏对话界面。
- 用户可以连续输入多轮问题，并让系统在当前运行会话内保留上下文。
- 系统可以通过配置在 Anthropic Claude 协议和 OpenAI 协议之间切换。
- 系统可以逐步展示模型回复，让用户在生成过程中看到内容。
- 当 Claude 返回 extended thinking 内容时，界面可以在独立的可折叠区域中呈现。
- 配置文件支持用户级默认配置和项目级覆盖配置。

## 功能需求
- F1: 启动后，JulyCode 必须进入全屏终端对话界面，界面至少包含历史消息展示区、当前输入区、回复生成状态提示，以及可退出当前会话的操作。
- F2: 用户提交一条消息后，JulyCode 必须调用当前配置的大模型后端，并把模型回复逐步显示在界面中，而不是等完整回复生成后一次性显示。
- F3: JulyCode 必须支持多轮对话，在同一次运行中把之前的用户消息和模型回复作为后续请求的上下文。
- F4: JulyCode 必须支持通过配置选择 Anthropic Claude 协议或 OpenAI 协议，并使用配置中的模型、请求地址和认证信息发起请求。
- F5: 配置文件必须使用 YAML 表达，核心配置字段包括 `protocol`、`model`、`base_url`、`api_key`。
- F6: JulyCode 必须同时支持用户级配置和项目级配置；当两者都存在时，项目级配置覆盖用户级配置中的同名字段。
- F7: `api_key` 必须支持直接填写密钥，也必须支持通过环境变量引用密钥；当环境变量缺失或为空时，必须给出可理解的错误提示。
- F8: 当使用支持 extended thinking 的 Claude 后端且返回可分离的思考内容时，JulyCode 必须在与最终回复分离的可折叠思考区中展示该内容。
- F9: 当配置缺失、协议不支持、认证失败、网络失败或后端返回错误时，JulyCode 必须在界面中展示清晰错误信息，并允许用户继续输入下一条消息或退出。
- F10: 用户必须可以通过明确的退出操作结束当前会话；退出后，本阶段不要求保存对话历史。

## 非功能需求
- N1: 流式展示必须在可用内容到达时尽快更新界面，避免长时间无反馈。
- N2: Provider 能力必须以统一行为对外呈现，使对话界面不依赖某个具体供应商协议的细节。
- N3: 配置错误和请求错误必须避免泄露完整密钥。
- N4: 第一版范围必须保持为纯对话能力，不引入工具调用、文件读写、代码编辑或自动执行命令。
- N5: 在常见终端尺寸下，界面文本必须可读，输入和输出区域不得互相遮挡。

## 不做的事
- 不实现 tool use、函数调用、shell 命令执行、文件读取、文件修改或代码编辑。
- 不实现跨启动的会话持久化、历史搜索或会话恢复。
- 不实现模型列表自动发现、模型价格展示或供应商账号管理。
- 不实现多会话并行、标签页或后台任务管理。
- 不实现语音、图片、附件或多模态输入输出。
- 不实现插件系统、权限系统或沙箱策略。

## 验收标准
- AC1: 启动 JulyCode 后，终端进入全屏对话界面，并能看到输入区、消息区和退出方式。
- AC2: 用户输入一条真实问题后，界面能逐步显示模型回复内容，而不是一次性刷出完整结果。
- AC3: 连续两轮对话中，第二轮问题能引用第一轮内容，并得到基于当前会话上下文的回答。
- AC4: 使用 Anthropic Claude 协议配置时，可以成功获得流式回复。
- AC5: 使用 OpenAI 协议配置时，可以成功获得流式回复。
- AC6: 同时存在用户级配置和项目级配置时，项目级配置的同名字段生效。
- AC7: `api_key` 使用环境变量引用时，环境变量存在则请求成功；环境变量缺失或为空时，界面显示清晰错误且不泄露密钥。
- AC8: 使用支持 extended thinking 的 Claude 配置并返回思考内容时，界面展示独立的可折叠思考区，最终回复仍在正常消息区域展示。
- AC9: 配置缺失、协议不支持、认证失败、网络失败或后端错误时，界面显示可理解错误，并且用户可以继续输入或退出。
- AC10: 退出并重新启动后，上一轮运行中的对话历史不会自动恢复。
