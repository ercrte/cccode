# Tool Call Nonblocking Spec

## 背景

当前 MewCode 在 Agent 调用工具时，终端界面会明显卡顿。已确认主要原因是部分工具虽然暴露为异步接口，但内部执行长耗时命令、搜索、脚本或大量文件扫描时会阻塞主事件循环，导致 TUI 刷新、输入响应、权限提示等用户可见交互延迟。

## 目标

- 工具执行期间，MewCode 的界面保持可刷新、可响应。
- 保持现有工具的输入输出语义、权限语义和超时语义不变。
- 让多个只读工具并发执行时，已完成的工具结果可以尽早反馈给界面。

## 功能需求

- F1: 当 Agent 执行本地命令类工具时，界面不应被命令运行过程阻塞。
- F2: 当 Agent 执行代码搜索、文件查找、文件读写或编辑等文件系统工具时，界面不应被大量文件或较慢 IO 明显阻塞。
- F3: 当 Agent 执行 Skill 专属脚本工具时，界面不应被脚本运行过程阻塞。
- F4: 当同一批只读工具并发执行时，单个慢工具不应阻止其他已完成工具的完成状态被反馈。
- F5: 权限确认流程保持现状：需要用户确认的副作用工具仍必须等待用户确认后才能执行。

## 非功能需求

- N1: 不降低现有安全边界，权限拒绝、沙箱校验和危险命令拦截行为保持一致。
- N2: 不改变工具返回的数据结构和错误类型，避免破坏模型上下文和现有测试。
- N3: 对慢工具仍保留超时保护，超时结果应可观测。
- N4: 改动应有单元测试覆盖，并通过现有测试集。

## 不做的事

- 不修改工具迭代上限。
- 不调整权限模式默认值。
- 不新增流式命令输出展示。
- 不重做 TUI 布局或权限确认 UI。
- 不改变模型调用流程和上下文压缩策略。

## 验收标准

- AC1: 执行一个持续一小段时间的命令类工具时，主事件循环仍能继续调度其他协程。
- AC2: 执行搜索或文件系统工具时，主事件循环不被同步扫描长期占用。
- AC3: 执行 Skill 脚本工具时，主事件循环仍能继续调度其他协程。
- AC4: 一批只读工具中，快工具完成后能先于慢工具产生完成事件。
- AC5: 现有权限确认、工具超时、错误包装和工具结果格式保持兼容。
- AC6: tmux 端到端场景中，触发工具调用后界面能展示工具状态并最终正常回复。
