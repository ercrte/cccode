# 工具迭代上限调整为 40 Spec

## 背景
JulyCode 使用 Agent Loop 连续请求模型、执行工具并回灌结果。当前主 Agent 的缺省迭代上限为 8，内置子 Agent 角色的显式迭代上限为 6；较长的真实编程任务可能在完成前触发上限。

本次调整将主 Agent、子 Agent 及内置子 Agent 角色的默认运行能力统一到最多 40 轮，同时保留用户通过配置显式指定其他正整数上限的能力。

## 目标
- 主 Agent 未显式配置迭代上限时，最多运行 40 轮。
- 子 Agent 未显式配置迭代上限时，最多运行 40 轮。
- 内置 `reviewer` 和 `code-searcher` 子 Agent 最多运行 40 轮。
- 保持现有迭代停止语义和显式配置覆盖能力不变。

## 功能需求
- F1: 主 Agent 未显式配置迭代上限时，系统必须使用 40 作为迭代上限。
- F2: 子 Agent 未通过委派请求或角色定义显式指定迭代上限时，系统必须使用 40 作为迭代上限。
- F3: 内置 `reviewer` 和 `code-searcher` 角色必须将迭代上限设为 40。
- F4: 用户为主 Agent、子 Agent 默认值、自定义角色或单次委派显式配置合法正整数时，系统必须继续遵循该显式值。
- F5: 达到实际生效的迭代上限后，系统必须沿用现有行为停止后续模型请求和工具执行，并向用户展示停止原因。
- F6: 用户文档中的主 Agent、子 Agent 和内置角色示例必须与新的 40 轮默认行为一致。

## 非功能需求
- N1: 调整不得改变 Agent Loop 的轮次计数方式、停止时机或事件类型。
- N2: 调整不得改变 OpenAI、Anthropic 等不同模型协议下的行为一致性。
- N3: 自动化测试必须覆盖主 Agent 默认值、子 Agent 默认值、内置角色值和显式覆盖值。

## 不做的事
- 不把 40 设为不可突破的硬上限。
- 不禁止用户配置大于或小于 40 的合法正整数。
- 不改变迭代上限的配置优先级。
- 不改变工具调度、权限、上下文管理或停止提示的业务逻辑。
- 不调整用户已有配置文件中的显式值。

## 验收标准
- AC1: 未配置主 Agent 迭代上限时，运行配置中的上限为 40。
- AC2: 未配置子 Agent 默认上限，且单次委派和角色均未指定上限时，子 Agent 的实际运行上限为 40。
- AC3: 加载内置 `reviewer` 和 `code-searcher` 角色时，两者的迭代上限均为 40。
- AC4: 分别显式配置主 Agent、子 Agent 默认值、角色和单次委派上限后，实际运行使用对应的显式正整数。
- AC5: 以较小显式上限运行持续请求工具的场景时，系统仍在该上限停止并展示迭代上限原因，证明停止语义未回退。
- AC6: README 中可观察到主 Agent 默认 40、子 Agent 默认 40，以及内置角色 40 轮的说明或示例。
