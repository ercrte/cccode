# MCP 工具延迟加载 Spec

## 背景
MewCode 已支持通过 MCP 接入 GitHub 等外部服务。当前启动时会发现每个 MCP Server 的全部工具，并在每次模型请求中携带所有工具的完整说明和参数约束。GitHub MCP 当前约有 45 个工具，仓库内样本估算其工具定义约占 9.4k tokens；即使用户请求与 GitHub 无关，这部分内容仍会重复占用上下文窗口。

本功能将 MCP 工具改为按当前用户轮次延迟暴露。MewCode 仍在启动阶段建立 MCP 会话并发现工具目录，但模型默认只看到一项轻量检索能力。模型判断需要 MCP 能力时，先按自然语言意图检索；下一次模型迭代只获得本次命中工具的完整定义。

## 目标
- 默认模型请求不再携带全部 MCP 工具定义。
- 模型可以按任务意图发现并调用此前未暴露的 MCP 工具。
- 延迟加载只增加一次必要的模型迭代，不要求用户手动选择工具。
- 已加载工具仅在当前用户轮次有效，不向后续轮次累积上下文开销。
- 保持现有 MCP 连接、OAuth、权限、工具执行和错误隔离语义。

## 功能需求
- F1: MewCode 启动时仍须连接已配置且可用的 MCP Server，并发现其工具目录；工具目录不得因延迟暴露而丢失名称、标题、说明或参数约束。
- F2: 新用户轮次开始时，模型默认不得收到任何 MCP 远端工具的完整定义，只能看到固定的轻量 MCP 工具检索能力，以及已连接 Server 的名称和工具数量摘要。
- F3: 模型必须能够使用自然语言任务意图检索 MCP 工具，并可选限定一个已连接的 MCP Server；检索范围必须覆盖已发现工具的名称、标题和说明。
- F4: 一次检索必须返回按相关性排序的有限候选，并自动将这些候选的完整定义暴露给下一次模型迭代；默认最多暴露 5 个候选，不得把完整工具目录写入检索结果。
- F5: 当前用户轮次内再次检索时，新的候选集合必须替换上一批候选，使任一模型请求中延迟加载的 MCP 工具数量始终不超过单次检索上限。
- F6: 检索无匹配、指定 Server 不存在或 Server 当前不可用时，必须返回结构化、可恢复的结果，允许模型调整查询后重试；不得退化为自动暴露全部 MCP 工具。
- F7: 候选工具暴露后，模型必须可以按现有全局工具名和完整参数约束调用它们；调用转发、结果回灌、超时和错误转换行为必须与当前 MCP 工具一致。
- F8: 延迟加载的工具必须仅在当前用户轮次内有效。模型正常回复、用户取消、迭代上限、上下文限制、供应商错误或其他终止路径结束当前轮次后，后续用户轮次不得继续收到上一轮加载的 MCP 工具定义。
- F9: MCP OAuth 授权成功后，新发现的工具必须可被检索；退出授权、授权失效或 Server 被移除后，其工具必须立即从可检索目录和当前候选集合中移除。
- F10: MCP 工具检索本身不得触发远端业务操作，也不得要求权限确认；实际调用命中的 MCP 工具时，仍须经过现有 Plan Mode、权限规则、调度和 Hook 流程。
- F11: 内置工具、系统工具、Skill 专属工具、子 Agent 工具和团队工具的暴露行为不得被本功能改变。
- F12: OpenAI 和 Anthropic 两类 Provider 必须获得语义一致的默认工具集合和延迟加载候选集合。
- F13: 状态信息必须能够区分已发现的 MCP 工具数量和当前轮次已暴露的 MCP 工具数量，便于诊断延迟加载是否生效。
- F14: 上下文预算估算必须使用当前实际暴露给模型的工具集合，不得继续按完整 MCP 工具目录计费。

## 非功能需求
- N1: 以当前约 45 个工具、约 9.4k tokens 的 GitHub MCP 样本为基准，未使用 MCP 的模型请求中，MCP 工具定义估算占用必须至少减少 90%。
- N2: 工具检索必须在本地已发现目录上完成，不得为检索额外调用第三方模型、外部搜索服务或 MCP 业务工具。
- N3: 检索结果必须稳定可复现；相同目录和相同查询应得到相同排序，相关性相同时使用稳定规则决定顺序。
- N4: 工具目录较大时，检索不得阻塞 Agent Loop；在 1,000 个工具的目录规模下，单次本地检索应在 100 毫秒内完成。
- N5: 工具说明、参数约束、Server 错误和 OAuth 信息必须继续遵守现有脱敏规则，不得在检索结果或状态信息中泄露凭据。
- N6: 延迟加载机制必须保持 Provider 无关，不能依赖某一家供应商特有的工具搜索协议。
- N7: 未配置 MCP Server、MCP Server 全部不可用或当前任务不使用 MCP 时，普通对话和现有工具调用行为不得回退。

## 不做的事
- 不延迟 MCP Server 的连接、初始化握手或工具目录发现。
- 不使用向量数据库、Embedding、RAG 或外部搜索服务进行工具检索。
- 不采用供应商专有的服务端工具搜索能力。
- 不在模型请求前由宿主自动猜测并预加载 MCP 工具。
- 不提供跨用户轮次的 MCP 工具缓存或会话级 LRU 保留。
- 不提供单一通用代理工具绕过完整参数约束直接调用任意 MCP 工具。
- 不修改 MCP 资源、提示词、采样或其他非工具能力的支持范围。
- 不改变远端 MCP 工具提供的原始参数约束和业务行为。
- 不为 GitHub MCP 手工维护专用分类表或工具白名单。

## 验收标准
- AC1: 配置包含大量工具的 GitHub MCP 后，首个普通对话请求只包含轻量 MCP 检索能力，不包含任何 `github__*` 远端工具完整定义。（覆盖 F1、F2）
- AC2: 用户提出 GitHub 相关任务时，模型可以先按自然语言意图检索；紧接着的模型请求包含不超过 5 个相关 `github__*` 工具的完整定义，并可成功调用其中工具。（覆盖 F3、F4、F7）
- AC3: 同一轮次连续执行两次不同检索后，第二次请求只包含第二批候选，不再包含第一批候选，且远端 MCP 工具定义总数不超过 5。（覆盖 F5）
- AC4: 检索无匹配、限定不存在的 Server 或限定不可用 Server 时，模型收到结构化失败或空结果并可修改查询重试，后续请求仍不会暴露完整目录。（覆盖 F6）
- AC5: 在正常完成、取消、迭代上限、上下文限制和供应商异常后分别开始新用户轮次，新请求均不包含上一轮激活的 MCP 远端工具定义。（覆盖 F8）
- AC6: OAuth Server 授权成功后，其工具可以被检索和调用；退出授权或授权失效后，其工具无法再被检索，已暴露定义也从后续请求中消失。（覆盖 F9）
- AC7: 检索操作不触发权限确认或远端业务调用；命中的 MCP 工具被实际调用时，仍执行现有权限、Plan Mode、调度和 Hook 规则。（覆盖 F10）
- AC8: 启用延迟加载后，内置工具、系统工具、Skill、子 Agent 和团队工具的可见性与调用行为保持现状。（覆盖 F11）
- AC9: 相同工具目录和查询重复检索得到相同排序；1,000 个工具的单次检索耗时低于 100 毫秒。（覆盖 F3、N3、N4）
- AC10: OpenAI 与 Anthropic 请求在同一运行状态下包含相同语义的 MCP 检索能力和候选工具集合。（覆盖 F12）
- AC11: 状态信息同时显示已发现工具数和当前轮次已暴露工具数；上下文估算只统计轻量检索能力及当前候选，不统计完整目录。（覆盖 F13、F14）
- AC12: 使用当前 GitHub MCP 样本估算未使用 MCP 时的请求占用，MCP 工具定义 token 数较全量暴露至少下降 90%。（覆盖 N1）
- AC13: 未配置 MCP、MCP 全部不可用以及普通非 MCP 对话三种场景均能正常完成，且现有全量自动化测试无回归。（覆盖 F11、N7）
- AC14: 在 tmux 中启动 MewCode，先发送普通代码请求，再发送真实 GitHub 请求；观察到前者不加载 GitHub 工具，后者先检索、下一迭代仅加载命中工具并完成调用，结束后新请求恢复为零个远端候选。（覆盖 F2、F4、F7、F8）
