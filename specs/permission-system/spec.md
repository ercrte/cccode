# JulyCode 权限系统 Spec

## 背景
JulyCode 已经具备本地工具系统、Agent Loop 和 Plan Mode。模型可以读取文件、写入文件、修改文件、搜索代码并执行本地命令，但当前只有 Plan Mode 的只读工具限制，缺少面向真实编程场景的统一权限系统。只依赖模型自觉遵守提示无法阻止危险命令、项目外文件访问或误操作；如果工具调用被拒绝后直接终止任务，也会让模型失去调整策略的机会。

本阶段要为 JulyCode 增加一套五层防御的权限系统：危险操作硬拦截、项目路径沙箱、可配置规则、权限模式和人在回路确认。权限系统必须在工具真正执行前做决策，并把拒绝结果作为可观察的工具失败回灌给模型，让 Agent Loop 能继续尝试更安全的方案。

## 目标
- JulyCode 可以在执行本地工具前统一判断工具调用是否允许、拒绝或需要用户确认。
- JulyCode 可以硬拒绝已知高危命令，且该拒绝不能被配置、权限模式或用户临时放行绕过。
- JulyCode 可以限制内置文件类操作只能访问当前项目目录内的路径，并阻止相对路径、绝对路径和符号链接逃逸。
- JulyCode 可以通过多层 YAML 规则声明细粒度 allow 或 deny，并按会话、本地、项目、用户的优先级逐层判断。
- JulyCode 可以通过权限模式整体调整信任等级，从严格确认到默认交互再到高信任放行。
- JulyCode 可以在规则未明确命中时向用户请求确认，并支持本次、本会话和永久三种放行范围。
- JulyCode 在权限拒绝后不终止 Agent Loop，而是把失败原因反馈给模型，允许模型调整下一步。

## 功能需求
- F1: JulyCode 必须在任何本地工具真正执行前进行权限检查；权限检查结果必须明确为允许、拒绝或需要用户确认。
- F2: 对本地命令执行，JulyCode 必须在执行前识别预定义高危命令模式；命中高危模式时必须直接拒绝执行。
- F3: 高危命令拒绝必须不可被用户级、项目级、本地级、会话级规则、权限模式或人在回路放行绕过。
- F4: 高危命令被拒绝时，JulyCode 必须返回结构化失败结果，说明拒绝原因，并保证命令没有启动。
- F5: 对内置文件读取、写入、修改、查找和搜索等文件类操作，JulyCode 必须把相关路径限制在当前项目目录内。
- F6: 路径判断必须以解析后的真实路径为准；相对路径上跳、绝对路径、符号链接或组合路径只要最终落在项目目录外，都必须被拒绝。
- F7: 项目路径沙箱必须优先于可配置规则和权限模式；任何规则或放行模式都不能允许项目目录外的内置文件类操作。
- F8: JulyCode 必须支持以 `工具名(模式)` 声明权限规则，规则结果只能是 `allow` 或 `deny`。
- F9: 规则模式必须支持精确匹配和 glob 匹配；匹配对象必须至少覆盖工具名以及该工具的关键参数、命令字符串或路径模式。
- F10: 权限规则必须支持用户级、项目级、本地级和会话级四个来源；优先级必须是会话级高于本地级，本地级高于项目级，项目级高于用户级。
- F11: 当多个规则来源同时匹配同一工具调用时，JulyCode 必须使用最高优先级来源的决策；较低优先级来源不得覆盖较高优先级来源。
- F12: 同一规则来源内同时存在多个匹配时，精确匹配必须优先于 glob 匹配；仍然冲突时，`deny` 必须优先于 `allow`。
- F13: 权限模式必须至少支持严格、默认和放行三档，并对没有被硬拒绝、沙箱拒绝或显式规则拒绝的工具调用生效。
- F14: 严格模式下，有副作用的工具调用即使命中 allow 规则，也必须交由用户确认；读类工具仍可按规则和默认策略执行。
- F15: 默认模式下，JulyCode 必须执行明确 allow 的工具调用，拒绝明确 deny 的工具调用，并把未明确命中的有副作用工具调用交由用户确认。
- F16: 放行模式下，JulyCode 必须自动允许未明确命中的工具调用，但仍必须执行高危命令硬拒绝、项目路径沙箱和显式 deny 规则。
- F17: 当权限系统需要用户确认时，界面必须展示工具名、关键参数、触发原因和可选决策，并暂停该工具调用直到用户选择。
- F18: 用户确认必须支持三种范围：仅本次允许、本会话允许、永久允许。
- F19: 本次允许只影响当前这一次工具调用；本会话允许必须在当前运行期创建最高优先级临时 allow 规则；永久允许必须写入持久化规则来源。
- F20: 用户拒绝确认时，JulyCode 必须拒绝当前工具调用，并把拒绝原因作为结构化失败结果回灌给模型。
- F21: 权限拒绝、用户拒绝、规则拒绝、沙箱拒绝和高危命令拒绝都不得直接终止 Agent Loop；只要未触发既有停止条件，模型必须有机会根据失败结果调整策略。
- F22: JulyCode 必须能加载用户级、项目级和本地级 YAML 规则；缺失的规则文件必须视为空规则，格式错误必须给出清晰配置错误。
- F23: JulyCode 必须在界面或状态事件中暴露权限等待、权限允许和权限拒绝状态，使用户能理解当前 Agent 为什么暂停或继续。
- F24: 权限系统必须与 Plan Mode 共存；Plan Mode 的只读限制仍然有效，不能被权限规则或放行模式解除。

## 非功能需求
- N1: 权限判断必须集中、可测试，并覆盖所有内置本地工具入口，避免不同工具各自实现互相冲突的权限逻辑。
- N2: 默认行为必须保守；当权限系统无法可靠判断一个有副作用工具调用是否安全时，必须拒绝或请求用户确认，而不是静默执行。
- N3: 权限失败结果必须包含足够信息供模型调整，但不得泄露配置密钥或敏感环境变量。
- N4: 权限确认期间，TUI 不得崩溃或丢失当前会话；用户做出决策后，Agent Loop 必须能继续处理后续事件。
- N5: 规则配置格式必须便于人工阅读和手写；无效规则必须以可理解方式报告，不应被静默忽略。
- N6: 权限系统必须保持 OpenAI 和 Anthropic 协议下的一致工具执行语义；供应商差异不得影响权限决策。
- N7: 本阶段必须聚焦本地工具权限，不引入网络访问控制、资源配额或审计日志。

## 不做的事
- 不实现网络请求限制、联网域名白名单或外部服务权限。
- 不实现 CPU、内存、进程数、磁盘空间或命令运行时长之外的资源配额。
- 不实现审计日志、审批报表或长期可追溯事件存储。
- 不实现操作系统级容器、chroot、虚拟机或完整进程沙箱；本阶段的路径沙箱只保证 JulyCode 可识别的内置文件类操作不会访问项目目录外路径。
- 不实现交互式命令会话、后台长期进程或命令运行中的二次输入确认。
- 不允许任何配置、权限模式或人工确认绕过高危命令硬拒绝和项目路径沙箱。
- 不改变现有模型供应商协议能力，也不新增网络搜索、浏览器或 MCP 工具。

## 验收标准
- AC1: 当模型请求执行命中高危模式的命令时，JulyCode 不启动命令，返回高危命令拒绝结果，并继续 Agent Loop。
- AC2: 高危命令即使被用户级、项目级、本地级或会话级 allow 规则匹配，也仍然被拒绝。
- AC3: 当文件类工具访问项目目录内的普通路径时，权限系统允许进入后续规则或模式判断。
- AC4: 当文件类工具通过 `..`、绝对路径或符号链接指向项目目录外时，JulyCode 拒绝操作，目标文件不被读取或修改。
- AC5: 当用户级规则允许某个工具调用而项目级规则拒绝同一调用时，项目级拒绝生效。
- AC6: 当项目级规则允许某个工具调用而本地级规则拒绝同一调用时，本地级拒绝生效。
- AC7: 当本地级规则允许某个工具调用而会话级规则拒绝同一调用时，会话级拒绝生效。
- AC8: 当同一来源内精确规则和 glob 规则都匹配时，精确规则的结果生效。
- AC9: 当同一来源内同等匹配能力的 allow 和 deny 同时匹配时，deny 生效。
- AC10: 默认模式下，明确 allow 的工具调用可执行，明确 deny 的工具调用被拒绝，未明确命中的有副作用工具调用进入用户确认。
- AC11: 严格模式下，有副作用工具调用即使命中 allow 规则，也会进入用户确认。
- AC12: 放行模式下，未明确命中的非硬拒绝工具调用可执行，但显式 deny、高危命令和沙箱拒绝仍然生效。
- AC13: 需要用户确认时，TUI 展示工具名、关键参数、触发原因以及本次、本会话、永久允许和拒绝选项。
- AC14: 用户选择本次允许后，仅当前工具调用继续执行；下一次相同未命中调用仍按权限系统重新判断。
- AC15: 用户选择本会话允许后，当前运行期内相同模式的后续调用自动允许，重启后不再保留。
- AC16: 用户选择永久允许后，相同模式的后续运行也可按持久化规则自动允许。
- AC17: 用户拒绝确认后，当前工具调用不执行，模型收到权限拒绝结果，并能继续尝试其他安全方案。
- AC18: Plan Mode 中即使存在允许写入或命令执行的权限规则，有副作用工具仍被拒绝，并把失败结果回灌给模型。
- AC19: 规则文件缺失时 JulyCode 正常启动并按空规则处理；规则文件格式错误时给出清晰错误，不以半解析状态继续运行。
- AC20: 权限等待、允许和拒绝状态可通过自动化测试或 TUI 行为观察到，并且不会导致输入区永久不可用。
